# 일주일 예측 2차 (21시 판단, 육지 D+2~D+7) — 설계 (R3)

> 담당: R3 가격 2차. 근거 문서: [ROLES.md](ROLES.md) 1·2절, 4.2·4.4절 / [01_결과.md](01_결과.md) 10·10-2·12절 / [OPS.md](OPS.md) '모델'.
> 상태: **① 설계 (2026-10-26) — 사용자 확인 대기**. 2026 자료는 아직 한 번도 보지 않았다.

## 0. 한 줄 요약

기준일 I의 21시에는 **내일(I+1) SMP·수요예측이 공표돼 있다**. 이 값을 넣어 I+2 ~ I+7 시간별 가격과 80% 범위를 다시 예측하고, 15시 1차 예측과 **같은 기준일·대상 날짜·시간끼리** 비교한다.
"내일 SMP만" (c)과 "SMP + 수요예측" (d)의 차이를 **수요 정보의 가치**로 따로 보고한다.

## 1. 21시 판단 정보 규칙 (ROLES.md 4.4)

| 정보 | 1차 (I일 15시) | 2차 (I일 21시) | 비고 |
|---|---|---|---|
| 시간별 SMP | I일까지 | **I+1일까지** (공표값) | 육지는 확정값(엑셀) = 하루전 공표값(API), 42,048시간 전부 일치 (`common/loaders.load_smp_actual`) → 과거 실적을 '공표값'으로 써도 됨 |
| 하루전 수요예측 | I일까지 | **I+1일까지** | (d)에서만 사용 |
| 날씨 예보 | 단기 11시(H=2~3)·중기 06시(H≥4) | **1차와 같음** | 21시 전 발표분(14·17시)은 팀 규칙상 쓰지 않음 |
| 주간 수요전망·연료비·태양광 설비·달력 | 판단일 I 기준 | **1차와 같음** | |
| Open-Meteo | H=1에서만 | 사용 안 함 | 1차와 같음 (H≥2) |

- **운영 = 요일 규칙 없이 공표 여부로 판단 (사용자 결정 2026-10-26)**: 실행할 때마다 I+1 공표 SMP 24시간이 있는지 확인 → **있으면 2차 모델, 없으면 1차 예측값·범위를 그대로** (`pub` = 1/0). 화요일 지연이든 다른 날의 누락이든 같은 방식이고, 23:30 재확인에서 공표가 잡히면 그때 2차로 바뀐다.
- **백테스트 = 가정 두 가지**: 과거 공표 시각 기록이 없으므로 성적은 두 가정으로 나눠 낸다.
  1. **항상 공표** (모든 기준일에 2차 모델) — 2차의 효과 크기
  2. **화요일 미공표** (화요일 판단 = 1차 값, ROLES.md 4.4) — 보수적인 운영 성적
  + 화요일 기준일만 따로 (공표됐다면 얼마나 나아지나)
- 지평 정의: H = 대상일 − 기준일 I, **H = 2~7** (1차와 같은 기준). 2차의 D+1은 공표값이라 만들지 않는다.

### 1.1 핵심 관찰 — Chronos는 새로 돌릴 필요가 없다
1차 Chronos-2 small(·Chronos-2)은 **SMP와 사전 확정 달력만** 입력으로 쓴다 (`wz_chronos.py`, `ops.chronos_rows`). 따라서
> **2차(I일 21시, 지평 H)의 Chronos 예측 = 1차(I+1일 15시, 지평 H−1)의 Chronos 예측** (입력이 글자 그대로 같음: SMP는 I+1의 24시까지, 공변량은 같은 달력)

- 백테스트: 이미 있는 `wzoo/c2s.csv.gz`·`c2.csv.gz`(대상 2025-01~)와 `wzoo_hist/c2s.csv.gz`(대상 2023~2024)를 **기준일 +1, H +1로 다시 붙이면** 된다 → Chronos 백테스트 재실행 없음 (수 시간 → 0). 2차 H=7 = 1차 H=6, 2차 H=2 = 1차 H=1.
- 확인: ②에서 몇 개 기준일을 실제로 다시 돌려 기존 값과 같은지 본다 (배치 구성 차이로 소수점 아래 차이만 있어야 함).
- 운영: `ops.chronos_rows([I+1])`를 (읽기 전용으로 불러) 호출하면 그대로 2차 Chronos가 나온다.
- 참고 추정(지시서): 지평이 하루씩 당겨지면 D+2~7 평균 MAE 9.91 → 약 9.48원 (팀 비교표 1차 D+1~6 평균). 단 잔차 보정의 날씨는 1차 그대로라 정확히 같지는 않다.

### 1.2 잔차 보정 피처 — 공용 코드 수정 없이
- 날씨·전망·연료비·달력 = 저장된 `features_hourly_육지_h{H}.csv` (`build(H)`, 판단일 I)
- 내일 공표 SMP·수요예측 = `build(H−1)`의 SMP·수요 열 (판단일이 I+1로 계산되므로 `s_d1` = I+1 같은 시간 SMP, `d_d1_h` = I+1 같은 시간 수요예측, `s_same_*`·`s_ma28`도 I+1까지)
- 두 표를 [date, hour]로 이어 붙이기만 하므로 `features.py`·`intervals.py`·`wz_*.py`는 **고치지 않는다** (읽기만). → 1차 출력 변화 없음.

## 2. 후보 (채점 전 고정)

공통: 최종 = Chronos-2 small 중앙값 + λ × 잔차 예측. 잔차 모델은 1차와 같은 LightGBM(L1, `wz_resid.LGB` 설정), **H별·매월 1일 재학습, 실적은 재학습일 − H일까지** (`wz_common.rolling_fit`과 같은 규칙), 학습 이력 2023-01~.

| 후보 | Chronos 입력 | 잔차 보정 피처 | 뜻 |
|---|---|---|---|
| **(a) 1차 그대로** (기준선) | I일까지 | 1차 '외부만' | `WZ_predictions_hourly.csv`의 H=2~7 그대로 |
| (b0) 참고 | **I+1일까지** | 보정 없음 (λ=0) | 내일 SMP의 '순수 시계열' 효과 |
| **(b)** | **I+1일까지** | 1차 '외부만'과 같은 정의 (Chronos 파생 `c_vs_d1` 등은 1차처럼 I일 SMP 기준), 새 Chronos로 다시 학습 | Chronos에만 내일 SMP |
| **(c)** | I+1일까지 | (b) + **내일 공표 SMP 피처**: Chronos 파생을 I+1 기준으로 다시 계산(`c_vs_d1`·`c_vs_same`·`c_vs_ma28`) + `p1_h`(I+1 같은 시간), `p1_mean`·`p1_min`·`p1_max`·`p1_midmin`(I+1 일평균·최저·최고·한낮최저), `p1_vs_d0`(I+1 − I 일평균), `p1_surprise`(I+1 일평균 − 1차 15시 Chronos가 본 I+1 일평균) | 내일 SMP를 보정에도 |
| **(d)** | I+1일까지 | (c) + **내일 수요예측 피처**: `dm_p1_h`(I+1 같은 시간), `dm_p1_mean`·`dm_p1_max`, `dm_p1_shape`(시간별/일평균), `dm_p1_vs_d0`(I+1 ÷ I 일평균), `kpx_peak_vs_p1`(대상일 주간전망 최대 ÷ I+1 수요예측 최대) | 수요 정보까지 |
| **(e)** 범위 | — | — | (a)~(d) 중 고른 점예측에 범위 방법을 지평별로 다시 고름 (3.2절) |

- λ 후보 {0.25, 0.5, 0.75, 1.0} (1차와 같음).
- **(c) vs (d) = 수요 정보의 가치**: 피처 차이가 수요예측 6개뿐이고 나머지(λ 선택 규칙·학습 기간·시드)는 같다.
- (b0)는 선택 대상에 포함하되 단순성 순위를 (a) 다음으로 둔다 (아래 3.1). → **확인 요청 1**

## 3. 선택 방법 (2025만 사용, 2026 채점 전 코드에 고정)

### 3.1 점예측 — 1차(`wz_ens`)와 같은 절차
1. λ: 후보마다 **2025 상반기 MAE**로 고름.
2. 비교: **2025 하반기 MAE** (H=2~7 전체 시간, 모든 기준일 — 화요일 대체 없이 모델끼리 비교).
3. 1위와 **0.05원 이내면 단순한 쪽**: (a) < (b0) < (b) < (c) < (d). → (b)~(d)가 (a)보다 0.05원 넘게 낫지 않으면 2차 모델은 만들지 않고 1차를 유지한다는 뜻.
4. 고른 후보의 λ를 2025 전체로 다시 맞춤 → 2026 예측.
- 2026 구간 학습은 매월 재학습(2023-01 ~ 그 달 직전 − H)으로, 1차 백테스트·운영 재학습과 같은 방식 (팀 규칙의 '2023~2025 재학습 → 2026'에 해당).
- 지시서는 "2025 검증 MAE"라고만 했는데, 1차와 나란히 비교하려고 1차 선택 절차(상반기로 맞춤 → 하반기 비교 → 전체로 재적합, `WZ_choice.json`)를 그대로 쓴다. → **확인 요청 2**

### 3.2 범위 (e) — 지평별, `intervals.select` 규칙
- 오차 이력: 2025-01~ 2차 예측 (1차와 같음; 이력이 2025-01부터라 365일 창 방법은 제외), 대상일 ≤ 기준일만 (gap = H).
- 후보 (지평 H마다): 1차 후보 그대로 — 오차 분위수형 (`intervals.methods`, 365일 제외), 보정 분위수 회귀(Chronos-2 분위수·갱신 90일·시간대묶음×휴무일), Chronos-2 분위수 그대로 (= 1차 H=2~7의 방법) + 추가 1종: Chronos-2 분위수를 λ × 잔차 예측만큼 이동.
  (분위수도 1.1절처럼 1차 Chronos-2 값을 하루 당겨 씀)
- 선택: **2025 하반기 전체 포함률 75~85% 중 구간점수 최소** (없으면 80%에 가장 가까운 것).
- 기준선 비교: '1차 방법 그대로'(Chronos-2 분위수 그대로)와 나란히 표기.

### 3.3 2026 한 번 채점 ('일주일 2차 예측 1차 시험')
- 기간: 대상일 **2026-01-01 ~ 10-18** (팀 공식 성적 기간). 고른 모델·범위로 한 번만.
- **1차와 같은 (기준일, H, 날짜, 시간)끼리** 나란히: MAE·RMSE·MAPE(20원 이상)·rMAE·편향·포함률·하한 아래·상한 위·평균 폭·구간점수 (`final_metrics.metrics`를 불러 씀) × 구간(전체·평일·휴무일·휴무일 한낮·급락 시간) × 지평(D+2~7) × 가정(항상 공표 / 화요일 미공표 / 화요일 기준일만).
  rMAE 단순 기준 = 지난주 같은 시간 (1차·팀 비교표와 같음).
- 차이의 불확실성: **날짜 단위 부트스트랩 95% 구간** (2차 − 1차 MAE, (d) − (c) MAE).
- 수요 정보의 가치 표: (d) − (c) MAE를 2025 하반기·2026 각각, 지평·구간별. (c)·(d) 중 무엇이 뽑히든 둘 다 2026을 계산하지만, **선택에는 쓰지 않는다**.
- 참고 행 (선택과 무관): ① 다음 날 15시 1차 (기준일 I+1, H−1 — 같은 대상을 18시간 뒤에 예측한 값; 2차가 그 대부분을 21시로 앞당기는지) ② 단순 기준 '내일 공표 같은 시간 그대로'.

### 4.1 운영 함수 (안)
```
wz2_ops.weekly(bases, stage="21h") -> DataFrame [base_date, H, date, hour, pred, lo, hi, offday, stage, pub]
  1) 기준일 I마다 I+1 공표 SMP 24시간이 있는지 확인 (load_smp_actual)
  2) 있으면: ops.chronos_rows([I+1]) → H+1로 바꿔 H=2~7 → 2차 잔차 보정 → 범위 (WZ2_choice)
     없으면 (화요일 지연 등): 1차 운영 기록(hourly_log)의 기준일 I, H=2~7 값을 그대로, pub=0
wz2_ops.train()   # 2차 잔차 보정 H별 재학습 (일요일, 1차 train과 함께) — 모델 없으면 weekly가 처음 한 번 학습
```
- 기록 파일은 쓰지 않는다 (운영 기록은 R0). 범위 방법이 오차 이력을 필요로 하면(보정 분위수 회귀 등) 이력 = 2차 백테스트 + R0가 정할 2차 운영 기록 경로.
- 21:30 `actuals`에서 공표 SMP 수집 뒤 호출, 23:30 재확인에서 `pub=0`이었던 기준일만 다시 호출.
- 소요 시간: Chronos 2종 1기준일 + LightGBM 예측 → 약 1분 예상, ④에서 실측.

**운영 함수·호출 순서**
```
from smp_forecast_app.src import wz2_ops
# 21:30 actuals: 공표 SMP 수집 뒤
w = wz2_ops.weekly([오늘], stage="21h")   # I+1 공표 24시간 있으면 2차(pub=1), 없으면 1차 hourly_log의 I, H=2~7 값(pub=0)
#   → 총괄이 기록 (예: ops/hourly2_log.csv). 열: base_date, H, date, hour, pred, lo, hi, offday, stage, pub, c2s, rhat
# 23:30/23:50 재확인: pub=0이었던 기준일만 다시 weekly → pub=1이면 덮어씀
# 일요일 train: ops.train() 뒤 wz2_ops.train()
```
- 전제: 같은 기준일의 1차(15:30) 기록이 `ops/hourly_log.csv`에 있어야 미공표 대체가 된다. 2차 범위의 오차 이력(D+2 보정 분위수 회귀)은 1차 운영 기록의 Chronos-2 분위수를 하루 당겨 쓰므로 **2차 기록 파일이 없어도 된다**.
- 소요 시간: `weekly` 1회 약 20초 (Chronos 2종 불러오기 + 피처 6개 생성, 기준일 3개도 20초), `train` 14초. 백테스트 재현: `wz2_backtest` 약 11분(잔차 보정 4종) + `wz2_select` 약 1분.
- 검증: 백테스트와 같은 학습 마감(10/1)으로 맞추면 운영 결과 = 백테스트 (예측 평균 차 0.03원, 범위 0.005원). Chronos는 재실행 값과 0.001원 차.
- 공용 코드·기존 파일 수정 없음 (`ops.chronos_rows`, `features.build`, `wz_resid.table`, `intervals`, `model.cqr`는 불러 쓰기만).

**성적 요약 3줄 (2026-01-01 ~ 10-18, 한 번 채점)**
1. 21시에 내일 공표 SMP를 넣어 2~7일 뒤를 다시 예측하면 MAE **9.91 → 9.61원 (−3.0%, 95% 구간 −0.37 ~ −0.22원)**, 6개 지평 모두 개선 (화요일 미공표 가정; 항상 공표면 9.53원).
2. 80% 범위 포함률 **76.6%** (기준 75~85% ✅), 폭 30.4원으로 1차(31.3원)보다 좁고 구간점수 52.4 → 50.3.
3. 내일 수요예측을 더하면 추가 개선은 **0.03원**뿐 — 내일 SMP 안에 수요 정보가 이미 들어 있다 (수요 정보의 가치 작음).

**발표 표현**
- "21시에는 내일 가격이 **공표돼 확정**되므로, 그 값을 받아 **2~7일 뒤를 갱신**한다" (21시 '내일 예측'이라고 하지 않는다).
- "갱신 효과의 대부분은 내일 공표 가격을 시계열 모델 입력에 넣는 것에서 나온다. 수요예측 추가 효과는 0.03원으로 작다."
- 성적은 "2026년 1~10월, 2025년까지로 고른 모델을 한 번 채점 (일주일 2차 예측 1차 시험)"으로 표기. 화요일 공표 지연은 보수적으로 1차 값을 쓴 성적이 공식.
- 급락 시간(30원 미만)은 2차도 범위 밖 → "급락은 경보가 담당" 유지.
