## 2. 운영 함수

```python
from smp_forecast_app.src import wz3_ops
r = wz3_ops.weekly(bases, stage="15h")   # 기준일 목록 → 위 열 + ckpt, c, rhat, ft_pred, ext_pred, c2_qlo, c2_qhi
```
- **호출 순서**: 15:30 daily의 수집 → `wz3_ops.weekly(밀린 기준일)` → (지금처럼) 한 달 → 급락·급등 → 근거 → 제주. 기존 `ops.weekly`(육지) 자리를 대신한다.
- **소요 시간**: 기준일 1개 약 1분 (피처 표 25초 + Chronos 3개 40초), 그달 첫 실행 +15초 (오차 보정 14개 자동 학습). 17개 기준일 한 번에 약 2분.
- **매월**: 할 일 없음 (자동). 일요일 `train`의 육지 `train_resid`는 K3에는 필요 없다 (제주 쪽 확인 전까지는 그대로 두는 것을 권함 — 4절).
- **매년**: 12월 31일 오전 `python -m smp_forecast_app.src.wz3_ops --finetune {그해}` (약 1시간, CPU 메모리를 많이 씀). 없으면 직전 판으로 예측하고 `[주의]`를 출력한다 → `ops_train.bat`에 12/31 1회 넣거나 달력 알림.
- 실패 시: 함수가 예외를 던진다 (기존 `run`처럼 감싸서 로그에 남기면 됨). SMP가 없는 기준일은 `[주의]` 출력 후 건너뜀.

## 3. 성적 요약 3줄
1. 2025 검증(고르는 데 쓴 기간): MAE **8.95원**, 포함률 79.7% (같은 시간끼리 7~12월: 지금 모델 9.21 → K3 8.96).
2. 2026 시험(1/1~10/18, 한 번 채점): MAE 지금 모델 9.664 → **K3 9.647** (−0.02원), 포함률 76.9% → **78.7%**, 구간점수 50.86 → 50.97 — **사실상 같은 수준**.
3. 1일 뒤 2026 MAE 8.20 → 8.17, 휴무일 한낮 19.24 → 19.02. 남은 큰 오차는 휴무일 한낮 급락(30원 미만, MAE 약 85원).

## 4. 연결할 때 주의 (중요)

1. **범위 하한 보정(`range_adjust`)을 K3 행에 적용하지 말 것.** `export_web`·`team_scorecard`가 육지 일주일을 읽을 때 휴일·주말 한낮 하한 × 0.85를 붙이는데, K3 범위(A1)는 보정 없이 골랐고 위 성적도 보정 없는 값이다.
2. **제주 일주일이 육지 예측을 입력으로 읽는다** (`jz_common.py` → `ops/hourly_log.csv`의 `pred`). 제주 모델은 지금 육지 모델 예측으로 학습돼 있어, `hourly_log`의 `pred`를 K3로 바꾸면 제주 입력 분포가 달라진다. 권장: R2 확인 전까지 **지금 육지 모델도 같이 돌려 제주 입력으로 유지**하거나 (`hourly_log`의 기존 열은 지금 모델, K3는 별도 기록·열), R2에 K3 입력으로 제주 재검증을 요청.
3. 운영 기록 열 대응 제안: `pred, lo, hi` = K3, `c2s` ↔ `c`(평일 미세조정판·휴무일 공변량판 중앙값), `rhat` ↔ `rhat`, `qlo, qhi` ↔ `c2_qlo, c2_qhi`, 추가 `ckpt`.
4. 웹·팀 비교표의 육지 일주일 백테스트 원본을 `WZ_predictions_hourly.csv` → `WZ3_K3_backtest_hourly.csv`로 바꾸면 된다 (열 같음, 2025-01-01부터라 기존보다 6개월 길다).
5. 기초모델은 Hugging Face 캐시를 쓴다 (`HF_HUB_OFFLINE=1` 그대로). 미세조정판은 `wz3/ft/ft2025f/` (107MB, git 제외 `data/`).
6. 시험 실행은 운영 기록을 건드리지 않는다. 단 `weekly`는 `k3_parts.csv.gz`에 그 기준일 구성값을 덮어쓴다 (같은 기준일을 다시 돌리면 같은 값).
