# 역할 분담과 할 일 (2026-10-28 개정, 총괄 작성)

> 근거: [read/SMP예측_1021수업_노션게시안_v1.docx](../../read/SMP예측_1021수업_노션게시안_v1.docx)(현업 10/21 답변), [공표경계 판정서 v1.2](../../read/참고자료.SMP예측_공표경계_판정서_v1.2.docx).
> **팀 공통 규칙**(루트 [CLAUDE.md](../../CLAUDE.md))이 우선: 데이터 13종만, 2023~2026 사용(2023~2024 학습 → 2025 검증 → 2023~2025 재학습 → 2026 한 번 채점), **급락 = 모든 날(평일 포함, 10/28 변경)**, 현재 모델 공식 성적 = 2026-01-01 ~ 10-18.
> **2026-10-28 현업 답변 반영**: ① 판단은 **15시 기준 하나**, 내일 SMP가 공표되면(보통 19시~, 23시까지 늦기도 함) 예측 대신 공표값으로 교체 — **21시 2차 예측은 하지 않는다** (아래 2절 표의 2차 열은 '공표 후 교체'로 읽는다, R3 21시 작업 종료). ② 급락은 평일에도 있다(제주 10/28 12시 0원) → 급락 학습·문턱·성적 = 전체 날. ③ 팀 최종 합의 모델: 육지 급락 = LSTM + LightGBM(확장 변수) 평균, 급등 = 부호 고정 점수 + 스플라인 로지스틱 + LightGBM 그루터기.
> 각 채팅은 이 문서의 1·2절, 자기 역할, 4절(공통 약속)을 먼저 읽는다.

## 1. 판단의 출발점 — SMP는 하루 전에 정해진다

- SMP는 전력거래소가 **하루 전에 계산해 정하는 가격**이다: 내일 수요 예측 → 발전사 공급가능용량 입찰 → 가격결정발전계획 → 시간별 SMP (재생에너지 클라우드 플랫폼: "1시간 단위로 전력거래 당일 하루 전에 결정").
- 그래서 **내일 SMP와 내일 수요예측은 같은 시각에 공표**된다. 평일 19~20시(화요일은 23시 지연·미공표 가능), 토·일은 14시 이전(일요일 새벽에 이미 나온 날도 있음). 21시 확보율 평일 88% (판정서 실측).
- 따라서
  - **다음 날 예측의 가치 = 공표 전(15시) 선행 정보.** 품질은 1차(15시)에 집중한다.
  - **21시에 내일은 '예측'이 아니라 '공표값 확정'**이다. 21시 다음 날 모델은 만들지 않는다.
  - 현업이 기대한 "다음 날을 다루면 일주일·한 달이 좋아진다"는 ① **21시에 내일 공표값을 받아 2~7일 뒤를 갱신**하는 것, ② **다음 날에서 수요–가격 관계를 배워 2~7일 뒤에 옮기는 것**으로 해석한다(10/28 현업 확인). 우리 다음 날 예측값 자체가 일주일에 보탬이 되는 길은 ③ **급락·급등 경보로 일주일 범위를 여는 것**뿐이다.

## 2. 운영 구조 (15시 예측 → 공표되면 공표값으로 교체)

| 예측 | 1차 (15시) | 2차 (21시) |
|---|---|---|
| 내일 급락 경보 | 모델 (R1 육지·R2 제주, 팀 규칙대로 재선택) | **공표 한낮 최저로 확정** (급락/아님) — 규칙, 모델 없음. 미공표(화 등)면 1차 유지, 23:30 재확인 |
| 내일 급등 경보 | 모델 (R4) | **공표 최고가로 확정** — 같은 방식 |
| 내일 시간별 가격 | 일주일 모델 D+1 | 공표 SMP (웹에 이미 표시) |
| 2~7일 뒤 가격 (일주일) | 지금 모델 | **2차 모델 (R3)**: 내일 공표 SMP(+수요예측)를 넣어 D+2~D+7 재예측 + 80% 범위 |
| 일주일 범위 (D+1) | **경보 → 범위 보정 (R0)**: 급락 경보 날 한낮 하한을 연다, 급등 경보 날 상한을 연다 | 2차 갱신분에도 같은 보정 |
| 한 달 | 지금 모델 (참고 전망) | 바꾸지 않음 |

- 운영 시각(총괄): 15:30 1차 · 21:30 2차(공표 확정 + 일주일 갱신) · 23:30 재확인(화요일 지연) · 늦게 켜지면 따라잡기.
- 보류(발표에서 '후속 과제'로): 21시 다음 날 모델, 자체 수요예측 모델, 한 달 개선.

## 4. 공통 약속 (총괄이 웹에 붙이는 형식)

### 4.1 경보 (급락·급등, 1차 15시)
- **백테스트**: `{담당 폴더}/outputs/tables/{kind}_{계통}_15h.csv` (kind = drop|surge)
  - 열: `base_date, date, grade, prob, score, label` — `grade` ∈ {없음, 주의, 경보}, `prob` = 보정 확률(0~1), `score` = 모델 점수(높을수록 위험, 없으면 빈칸), `label` = 실제 1/0 (**급락은 휴일·주말만, 평일은 빈칸**; 미확정 빈칸). 2025-01-01부터.
- **운영 함수**: `predict(bases) -> DataFrame` (위 열, label 제외). 기준일 15시까지 자료만. 하루 소요 시간 명시.
- **설정**: `{kind}_choice_{계통}.json` — 모델·피처·문턱(주의·경보)·확률식·선택 절차·학습 기간.
- **성적표**: `{kind}_score_{계통}.csv` — 기간(2025 검증 / 2026 시험 2026-01-01 ~ 10-18) × {일수, 급락(급등)일, PR-AUC, ROC-AUC, Brier, 헛경보@재현율80%·90% (+ 날짜 부트스트랩 95% 구간), 실전 주의 이상·경보 각각 적중·놓침·헛경보·재현율·정밀도·헛경보율}. 계산은 `smp_forecast_app/src/team_scorecard.py`의 경보 지표와 같게.
- 2차(21시)는 공표값 확정이라 총괄이 처리한다 (모델·파일 불필요).

### 4.2 가격 (시간별)
- 백테스트: `WZ_predictions_hourly.csv`와 같은 열 + `stage` (`base_date, H, date, hour, y, pred, lo, hi, offday, stage`), 2차는 `stage = 21h`, H = 2~7.
- 운영 함수: `weekly(bases, stage)` → 같은 열, 하루 소요 시간 명시.
- 성적표: `final_metrics.py`·`team_scorecard.py`와 같은 표준 지표(MAE·RMSE·MAPE·rMAE·편향·포함률·하한 아래·상한 위·평균 폭·구간점수) × 구간(전체·평일·휴무일·휴무일 한낮·급락 시간)·지평. **1차와 같은 날짜·시간끼리 나란히.**

### 4.3 이름·표기
- 경보 단계 **없음(낮음) / 주의 / 경보** (기존 `강한 경보` 값은 웹이 `경보`로 읽음). 예측 이름 **내일 급락 경보 · 내일 급등 경보 · 일주일 예측 · 한 달 예측**, 단계 **1차(15시) · 2차(21시)**.
- 재현율 = 실제 급락(급등)일 중 미리 경보한 비율, 정밀도 = 경보한 날 중 실제 비율, 헛경보@재현율80% = 시험 기간 안에서 급락의 80%를 잡도록 문턱을 맞췄을 때 헛경보 일수(순위 비교용). '실전' = 2025로 미리 정한 문턱의 성적.

### 4.4 21시 판단 정보 규칙 (R3 2차 백테스트)
- 기준일 I의 21시 = 1차 정보 + **I+1 공표 SMP·수요예측**. 과거 공표 시각 기록이 없으므로 **화요일 판단(수요일 대상)은 미공표로 보고 1차 값을 쓰며 성적을 따로** 낸다. 날씨는 1차와 같은 출처.

### 4.5 보고
- 단계마다 결과 요약 → 사용자 확인 → 다음 단계. 결정은 자기 문서의 결정 기록에.
- 끝나면 총괄에게: 산출 파일 경로, 운영 함수 이름·호출 순서·소요 시간, 성적 요약 3줄, 발표 때 지킬 표현.
