# 과제3 예측 근거 문장 (R5) — 형식·운영

> 범위: 육지 **내일 급락 경보**(LSTM + LightGBM 평균)와 **내일 급등 경보**(부호 고정 + 스플라인 + 그루터기). 일주일·한 달은 고도화 뒤.
> 코드: `src/reason_drop.py`, `src/reason_surge.py`, `src/reason_web.py` (모델 코드·결과는 읽기만).

## 1. 웹에 붙이는 파일 — `outputs/tables/R5_why_육지.json`

웹 `data.ts`의 `why` 자리와 같은 모양이다. 총괄 `export_web.py`에서 `land["why"] = {k: v for k, v in json.items() if k != "meta"}`만 넣으면 된다.

```json
{
 "meta": {"made": "...", "region": "육지", "비교 대상": {...}, "표시 문턱": {...}, "dir": "..."},
 "drop":  {"2026-01-18": [{"t": "지난 휴일(1/17) 한낮 가격이 0원까지 내려갔습니다", "dir": "up"}, ...],
           "2026-03-26": [{"t": "내일 최대 전력수요가 69GW로 높게 전망됩니다 (주간 전망)", "dir": "down"}, ...]},
 "surge": {"2026-11-01": [{"t": "내일은 휴일이라 전력 수요가 적어 급등 경보를 내지 않습니다", "dir": "down"}]}
}
```

- 줄마다 `v` = **근거별 영향** (2026-11-04 추가, 현업 요구 "요인별 부호·원 단위, 소수점 1자리"): 급락 = 예상 한낮 최저 가격에 미친 영향(원, 예 `"−36.6원"`), 급등 = 카드에 보이는 확률에 미친 영향(%p, 예 `"+6.8%p"`). 고정 문장(`none`)·급등 휴일 줄은 `v` 없음. 웹은 문장 오른쪽에 값, 아래에 "숫자 = 근거별 … 영향 (… 과 비교)" 한 줄.
- 열쇠 = **대상일**(경보 카드의 날짜). 문장 = 판단일 기준 말투("오늘" = 판단일, "내일" = 대상일).
- **근거는 항상 판정과 같은 방향**: 주의·경보 = 모두 `up`(▲), 없음 = 모두 `down`(▼). 결과와 어긋나는 줄은 내지 않는다.
- 줄 수 = 1~3 (확실한 근거만). 판정 방향의 근거가 문턱을 못 넘은 드문 날(2026: 급락 1일·급등 2일)은 고정 문장 한 줄, `dir: "none"`:
  - 없음: "급락(급등) 위험 신호가 일부 있지만 주의 기준에는 못 미쳤습니다"
  - 주의·경보: "작은 급락(급등) 위험 신호 여러 개가 겹쳐 주의(경보) 기준을 넘었습니다"
- 기간: 급락 2025-01-01 ~ 내일, 급등 2026-01-01 ~ 내일 (급등 2025는 저장된 모델이 2023~2025 학습이라 학습 구간 안 → 내지 않음).

## 2. 계산용 긴 표 — `outputs/tables/R5_reason_육지.csv`

| 열 | 뜻 |
|---|---|
| base_date, date | 판단일, 대상일 |
| kind | drop / surge |
| grade, score | 경보 등급·점수 (R1·R4 백테스트와 같음 — 급락 656일·급등 302일 등급 불일치 0) |
| rank | 줄 순서 1~3 (고정 문장 = 0) |
| t, dir | 문장, 방향 (위와 같음) |
| group, feature | 근거 묶음(현업 말), 문장 틀을 고른 피처 |
| base | 비교 대상의 점수 (급락 원, 급등 세 확률 평균) |
| contrib, unit | 묶음 기여. 급락 = 예상 한낮 최저 변화(원, 음수 = 위험↑), 급등 = 세 확률 평균 변화(양수 = 위험↑) |
| v | 화면 표시 값. 급락 = contrib 그대로(원), 급등 = contrib를 화면 확률(Platt 보정) 변화로 옮긴 %p — '확률 − 기준 확률'을 점수 기여 비율대로 나눔 |

## 3. 운영

- 전체 다시 만들기(재학습·문턱 변경 뒤): `python -m smp_forecast_app.src.reason_web` (약 3~10분).

## 4. 계산 방법 (요약)

**"왜 이렇게 나왔나"를 보여 주도록 결과에 따라 비교 대상을 고른다.**

| 판정 | 비교 대상 | 보여 주는 근거 |
|---|---|---|
| 주의·경보 | 평소 날 (급락 = 학습 구간 전체, 급등 = 학습 구간 평일) | 위험을 높인 것 (▲) |
| 없음 | 위험했던 날 (급락 = 학습 구간에서 한낮 최저가 주의 문턱 83원 이하였던 날, 급등 = 학습 구간 급등 평일) | 위험을 낮춘 것 (▼) |
| 급등 휴일 | — (모델 규칙상 0점) | 고정 한 줄 (▼) |

| 경보 | 방법 |
|---|---|
| 급락 | LightGBM TreeSHAP(비교 대상 날들의 평균을 빼 기준을 옮김) + LSTM 묶음 가리기 Shapley(7묶음, 128조합, 시드 5개, 가린 값 = 비교 대상의 흐름 평균·중앙값) → 각 ÷ 2 |
| 급등 | 세 모델 모두 로짓이 피처별 항의 합 → 비교 대상 평균을 빼 정확 분해, 확률로 옮겨 ÷ 3 |

- 기여의 합 + 기준 = 모델 점수 (코드에서 매번 확인). 묶음 기여가 급락 10원·급등 0.05 이상일 때만 문장. 문장 틀은 묶음 안에서 기여가 가장 큰 피처로 고르고, 실제 값이 방향과 어긋나면 그 틀은 건너뜀.
- '높다'는 말은 평소 수준 이상일 때만 쓴다 (위험했던 날보다 높아도 평소보다 낮으면 "크게 내려가지 않았습니다").
- 묶음: 급락 = 지난 같은 유형 날 · 최근 흐름 · 전력 수요 · 날씨 예보 · 달력 · 태양광 설비 · 연료비, 급등 = 오늘 가격 · 최근 최고 가격 · 가격 수준 변화 · 최근 급등 · 전력 수요 · 기온 · 흐림·비 · 달력.
