# 인계: 제주 급락 — 새 판정 기준(0원 이하, 시간 구간)으로 모델 다시 고르기 (11/11 발표용)

너는 SMP 예측 프로젝트(숙명여대 P4, 한국중부발전)의 **제주 급락** 부분을 맡는다. 자료 수집부터 모델 선택·채점까지 이 채팅이 한다. 육지 급락·급등은 다른 채팅이 같은 폴더에서 하고 있다.
**웹 운영 모델·공식 성적과 분리된 작업**이다. 작업 폴더는 `extended_backtest/`이고, 제주 파일은 이름에 `jeju`를 붙인다(예: `src/jeju_*.py`, `outputs/tables/J*_*.csv`). 육지 파일은 건드리지 않는다.

## 먼저 읽을 것
1. 루트 `CLAUDE.md`: 누수 금지, 판단 시각 = 전날 15:00, 시간 순서 분할만, 한국어, 단계마다 보고하고 확인받기.
2. `extended_backtest/CLAUDE.md`, `extended_backtest/docs/PLAN.md`: 판정 기준 요약, ① 사건 집계 결과.
3. `read/SMP예측_1104수업_판정기준_노션게시안_v1.1.docx`: 기준 문서. python-docx가 없으니 zipfile로 `word/document.xml`을 읽는다.
4. 지금 제주 모델 기록: `smp_forecast_app/docs/JEJU.md`, `drop_classifier/docs/PLAN.md` 결정 기록(2026-10-19·23·25·28), 코드 `drop_classifier/src/jeju_zoo.py`·`jeju_team.py`. 피처를 다시 쓸 때 참고만 하고, 고치지 않는다.

## 기준이 어떻게 바뀌었나
| | 지금 운영 모델 | 새 기준 (11/11 발표) |
|---|---|---|
| 사건 | 11~15시 최저 < 30원 | **SMP ≤ 0원** (음수 포함), 하루 전체 시간 |
| 단위 | 하루 | **연속 시간 구간** (하루 안에서 끊기면 2구간) |
| 판정 | 이진 분류 | 성공 = 그날 경보 / 부분 = 주의만 / 실패 = 없음. 하루 경보는 그날 모든 구간에 적용 |
| 헛경보 | – | 주의·경보를 냈는데 그날 0원 이하 시간이 없던 날 수 (주의·경보 나눠서) |
| 모델 | S5 + KNN 분류 (2026-10-25) | **다시 고른다** |

## 이미 확인한 것 (2026-11-05)
- **사건 수**: `python -m extended_backtest.src.events` → `outputs/tables/E1_intervals_jeju_zero.csv`. 제주 0원 이하 135구간(휴일 62 / 평일 73), 사건일 126일, 모두 2024년 이후.
  - 연도별(휴일/평일): 2024 10/17, 2025 29/30, 2026(~10/31) 23/26.
  - 부서 표는 62/72다. 1건 차이는 2024-12-05(목) 13시 — EPSIS 확정값 0원, 교육용 파일 137.36원. 우리는 EPSIS를 쓴다.
  - '정확히 0원'으로 세면 133구간이라 부서와 안 맞는다 → 0원 이하로 확정. 음수 시간은 2024년 이후 76시간.
  - 반기별 구간 수: 2024 상반기 5, 하반기 22, 2025 상반기 48, 하반기 11, 2026 상반기 39, 하반기 10. 월별로는 3~4월·10~11월에 몰리고, 6~8월에는 거의 없다.
- **SMP 로더**: `extended_backtest/src/data.py`의 `load_smp_all("제주")` (2020 ~ 최신), 휴일 = `offday_flags` (주말·공휴일).
- **제주 5분 실적 2020년분**: 데이터포털 API(`common/collect/kpx_jeju_sukub.py`의 `fetch_day`)로 2020-01-15·2021-06-15·2022-03-15·2023-11-15 모두 288행이 온다(2019-12-01부터 제공). 지금 저장된 건 2023-01·02, 2026-10·11 네 달뿐이고, 운영 모델은 2024~를 다른 내려받은 파일로 썼다 → 실제로 어디서 읽는지 `common/loaders.load_kpx_jeju_sukub`부터 확인.
  - **이 채팅이 수집한다** (사용자 결정, 2026-11-05). 저장은 `data/raw/backfill_2020/kpx_jeju_sukub/`, 코드는 운영 수집기를 고치지 말고 `extended_backtest/src/`에 새로 둔다. 약 1,460회 호출.
  - 주의: 2021-06-15 12시 태양광 23MW로 2020-01(59MW)보다 낮다 → 받으면 값부터 점검.
  - 제주 0원은 2024년 전에 없으므로, 2020~2023 자료는 급락 사례를 늘리지 않고 평소 날만 늘린다.

## 육지에서 확정한 학습·시험 방식 (2026-11-06, 제주도 같은 틀 권장, 최종 결정은 사용자)
- 시험 = **2025-01-01 ~ 2026-10-31** (부서 참고안과 같음, 2026은 「2차 시험」). 학습과 시험은 완전히 분리.
- 규칙 두 줄: ① 매달, 그 전달 말까지의 자료로 학습해서 그달을 예측한다. ② 그달의 주의·경보 문턱은 바로 앞 12개월의 '앞으로만 예측' 결과로 정한다.
- 시험 직전 한 번 자른 모델로 문턱을 정하는 안은 폐기됐다 (그 모델은 급락을 거의 못 본 상태라 문턱이 맞지 않음 — 사용자 지적).
- 시험 초반 문턱이 거친 것은 받아들이고, 나중에 틀린 날 분석에서 '학습 기간에 사건이 적었던 영향'으로 보인다 (사용자).
- 제주는 사건이 2024년부터라, 2025-01 문턱용 앞 12개월(2024년) 예측을 낼 모델이 거의 사건을 못 본다. 이 점을 먼저 따져서 사용자에게 제안한다.
- 육지 구현 참고: `extended_backtest/src/drop_walk.py`.

## 진행 순서 제안
0. 제주 5분 실적 2020~2023 수집 → 값 점검(빈 날, 태양광 이상치) → 보고.
1. 새 레이블 만들기: 날짜별 '0원 이하 시간 있음' + 구간 수 (판정은 하루 경보 → 그날 모든 구간).
2. 학습·시험·문턱 방식 결정 → 사용자 확인.
3. 후보 모델을 **채점 전에** 정해 두고(지금 KNN, 기존 후보 일부, 단순 규칙 기준선), 학습 구간 안의 앞으로만 예측으로만 고른다. 시험 구간으로 고르지 않는다.
4. 고른 모델로 시험 구간 한 번 채점 → 표 1(구간 수·성공·부분·실패, 휴일/평일), 표 2(헛경보, 주의/경보), 혼동행렬. 표 아래에 시험 기간·학습 기간·예측 시점(전날 15시).
5. 발표용 한 줄 결론과 핵심 숫자.
