# 역할별 주요 지시와 배운 점

> 2026-11-04 기준. 각 역할 채팅에서 **결과를 실제로 바꾼 지시**만 골라 모았다. 사소한 진행 지시는 뺐다.
> 맨 앞 1절은 여러 역할에서 공통으로 효과가 있었던 지시 방식이다. 직접 해 볼 때는 1절만 읽어도 된다.

## 1. 공통으로 효과가 있었던 지시 방식

| 방식 | 효과 | 나온 곳 |
|---|---|---|
| **채택 규칙을 결과를 보기 전에 먼저 문서에 고정**하게 한다 (어떤 지표로, 얼마나 좋아져야 채택하는지). 시험 연도(2026)는 마지막에 한 번만 채점한다 | "2026을 보고 고쳤다"는 의심 없이 채택·미채택을 판정. 10여 가지 시도 중 기준을 넘은 것만 남고, '쓰지 않음' 결론도 깔끔하게 남는다 | 모든 역할 |
| **선택 지표는 처음부터 현업이 평가하는 기준**으로 정한다 (급락: 80%를 잡을 때 헛경보 수) | 처음에 PR-AUC로 골랐다가 현업 기준과 달라 다시 골라야 했다 | R1 |
| **우선순위를 한 줄로 못박는다** ("1순위 놓치지 않기, 2순위 헛경보 줄이기") | 지표마다 우열이 갈려도 바로 고를 수 있다 | R4 |
| **이름만 맞추지 말고 원본을 먼저 재현한 뒤 개선**한다 | 구성 이름만 같고 세부를 새로 정했더니 사실상 다른 모델이 나왔다. 팀원 코드를 그대로 재현한 뒤 개선하는 순서로 다시 했다 | R4, R6 |
| **"운영은 그대로, 실험은 따로"**로 범위를 정한다 | 매일 돌아가는 예측을 건드리지 않고 새 자료를 시험할 수 있다 | R1, R4 |
| **"나아지면 수집하자"처럼 조건을 걸어** 새 자료를 들인다 | 효과를 먼저 확인해 쓸모없는 수집을 막는다 (변동비 순위는 효과가 없어 수집 요청을 안 함, 가스요금은 효과가 같고 공개 자료라 채택) | R0, R6 |
| **같은 코드에서 하나만 바꿔 비교**하게 한다 | 모델 효과와 연료 입력 효과를 따로 떼어 볼 수 있다 | R6 |
| **걱정·의심을 질문으로 던진다** ("휴일이라만 나오지 않을까?", "제주만 다른 게 있을 텐데?") | AI가 짐작으로 답하지 않고 지난 자료로 직접 세어 확인한 뒤 방향을 정한다. 평균에 묻힌 구간(제주가 육지와 다른 8%의 시간)이 개선 방향이 됐다 | R2, R5 |
| **문제는 원인에서 고친다** | 근거 문장이 결과와 어긋났을 때 화면 문구로 덮지 않고 근거를 고르는 방식을 바꿨다 | R0, R5 |
| **문제 정의(판단 시점·대상)를 먼저 의심**한다 | 한 달 예측은 모델을 키우는 것보다 '월말에 다음 달을 본다'는 판단 시점과 대상 달 연료 정보가 더 중요했다 | R6 |

## 2. 역할별 주요 지시

### R0 총괄·웹·운영
최종: 네 예측(급락·급등·일주일·한 달)을 매일 15:30 자동으로 계산해 웹에 보여 주는 서비스. 육지·제주.

| 날짜 | 지시 | 바뀐 것 |
|---|---|---|
| 10/28 | "우린 서비스를 만드는 거다. 불필요하게 자세한 정보는 필요 없다. 사용자가 이해되느냐, 쓰기 편한가가 가장 중요하다" | 화면을 '경보 카드 + 근거 문장' 중심으로 바꾸고, 내부 용어·실험 정보는 참고 문서로 옮김 |
| 11/01 | "변동비 자료를 꾸준히 모을 수 없다면 의미 없다. 먼저 예측이 나아지는지 확인하라" | 실험 결과 개선이 없어 피처로 쓰지 않고 수집 요청도 하지 않음 |
| 11/03 | "내일 하루뿐이라도 보정으로 나아지면 좋다. 눈으로도 보인다" | 내일 범위를 급락 경보에 맞춰 넓히는 규칙을 2025로 고르고 2026을 한 번 채점해 적용 (급락 시간 포함 0% → 88%) |
| 11/03 | "보정은 모델 성능이 아니라 웹에서 보기 좋게 하는 것" | 공식 성적표는 화면용 보정 전 범위로 채점 |
| 11/03 | "모델이 다 확정인데 비교표가 필요한가?" | 비교용 표를 '최종 모델 성적표'로 정리하고 급등까지 모음 |
| 11/03 | "현업은 저장소가 아니라 이 폴더만 받는다" | 프롬프트·데이터 문서를 폴더만으로 따라 할 수 있게 다시 씀 |

### R1 내일 급락 경보 (육지)
최종: LSTM과 LightGBM이 각각 내일 한낮 최저 가격을 예측하고 평균. 2026 급락 20일 중 17일을 '주의 이상'으로 미리 알림, 헛경보 31일 (이전 모델 82일).

| 날짜 | 지시 | 바뀐 것 |
|---|---|---|
| 10/28 | "구성은 팀 합의로 고정, 세부는 우리가 정한다. 고르는 근거는 2025뿐, 급락은 평일 포함 모든 날" | 문턱을 모든 날 기준으로 다시 정해 평일 헛경보 34일 → 4일 |
| 10/28 | "급락일이 적으니 과적합 주의" + "분류 대신 회귀로" | 설정 튜닝 없이 고정, 여러 번 학습해 평균, 두 학습 기간 중 나쁜 쪽으로 비교. 목표를 '한낮 최저 가격 예측'으로 바꾸고 선택 기준을 현업 평가 방식으로 → 2025 헛경보 41일 → 21일 |
| 11/01 | "변동비 순위가 도움이 되는지, 공개 시점 두 가지로 가정해 확인. 운영 모델은 그대로" | 모든 후보가 2025 성적을 떨어뜨려 미채택. 자료 문제 2건을 찾아 현업 확인 거리로 넘김 |

### R2 제주
최종: 일주일 = 육지 일주일(K3) + 제주 보정, 급락 = KNN 모든 날(2026 급락 53일 중 45일 포착), 한 달 = 육지 예측 그대로, 급등 = 제외.

| 날짜 | 지시 | 바뀐 것 |
|---|---|---|
| 11/03 | "육지 모델이 바뀌었으니 그것부터 확인하고, 제주 단독이 더 나으면 그래도 된다" | 제주 전체를 육지 새 모델 기준으로 다시 고름. 이전 육지 모델 없이 제주가 돌게 됨 |
| 11/03 | "제주는 제주가 다른 시간을 맞춰야 한다. 제주 피처를 더 상세하게" | 오차를 '제주 = 육지인 시간 / 다른 시간'으로 나눠 진단, 시간별 제주 정보를 새로 만들고 고르는 기준을 '다른 시간을 잘 맞히는 쪽'으로 바꿈 (그 시간 오차 13.2 → 12.2원) |
| 11/03 | "급등은 빼고 설명에 이유를 남기자" | 모델을 만들어 무작위 수준임을 확인한 뒤 제외, 웹·발표에 이유를 넣음 |

### R3 일주일 예측 (육지)
최종: K3. 평일은 SMP로 1년에 한 번 미세조정한 Chronos, 휴무일은 날씨·수요전망을 함께 넣은 Chronos, 남은 오차는 LightGBM으로 보정. 2026 MAE 9.65원, 포함률 78.8%.

| 날짜 | 지시 | 바뀐 것 |
|---|---|---|
| 10/28 | "할 수 있는 것은 다 해 보되 과적합 주의" | 개선 후보와 채택 기준(2025 오차 0.05원 넘게 개선)을 먼저 정함. 첫 결과는 지금 모델과 거의 같았음 |
| 11/01 | "할 수 있는 건 다 해 봐라" | 공급 자료·다른 기초모델·미세조정·구조 변경을 한꺼번에 시험. 낮은 학습률 미세조정만 기준을 넘어 K3 채택 |
| 11/01 | "자료가 바뀌니 정기적으로 다시 학습해야 하지 않나?" | 분기 vs 연 1회 재학습 차이가 0.004원뿐 → 연 1회로 정해 운영 부담을 줄임 |
| 11/03 | "K3로 확정하고 현업이 따라 할 수 있게 정리하라" | 매일 1분 운영 방법과 안내서를 만들고, 12월 말의 작은 정보 누수를 바로잡음 |

### R4 내일 급등 경보
최종: 팀 합의 모델 v3(부호 고정 점수 + 스플라인 로지스틱 + LightGBM 그루터기 평균). 2026 급등 7일 중 주의 5일(헛경보 101), 경보 2일(헛경보 1) — 참고 성적.

| 날짜 | 지시 | 바뀐 것 |
|---|---|---|
| 10/28 | "세부는 우리가 정한다. 다 해 봐" | 자체 설계(v1)는 검증은 좋았지만 2026에서 실패 |
| 10/28 | "2026을 보고 고친 게 아니라 똑같이 만들지 못한 것이니 다시 하라" | 팀원 코드를 받아 그대로 재현(v2, 날짜별 점수 거의 일치) |
| 10/28 | "1순위 급등일 잡기, 2순위 헛경보 줄이기" | v2를 기준으로 헛경보 줄이기 후보 4개를 검증해, 잡는 날은 그대로 두고 헛경보를 약 1/3 줄인 안 채택(v3) |

### R5 경보 근거 문장
최종: 급락·급등 경보마다 '왜 이렇게 예측했나'를 쉬운 문장 1~3줄로 자동 생성. 근거 기여의 합 = 모델 점수, 2025~2026 전체에서 결과와 방향이 어긋난 근거 0줄.

| 날짜 | 지시 | 바뀐 것 |
|---|---|---|
| 11/01 | "현업이 이해하기 쉬운 게 중요. 3줄을 다 채우지 않아도 되니 확실한 근거 위주로" | 기여가 작은 근거는 빼고 1~3줄만. 가격 근거를 뜻별로 나눠 "오늘 최고 가격이 평소보다 41% 높았다" 같은 구체적 사실이 나오게 함 |
| 11/02 | "결과는 '낮음'인데 근거가 모두 위험을 높이는 쪽이라 모순이다. 왜 이렇게 나왔는지를 근거로 들어라" | 주의·경보 날은 평소 날보다 위험을 높인 근거만, 낮음 날은 위험했던 날보다 위험을 낮춘 근거만 보여 주게 바꿈 |

### R6 한 달 예측 (육지)
최종: 매월 마지막 날 다음 달 모든 날의 일평균 + 80% 범위. LightGBM + 가스공사 발전용 가스요금. 2025 검증 7.54원(회사 변동비판 7.43원과 같은 수준), 2026 참고 10.98원.

| 날짜 | 지시 | 바뀐 것 |
|---|---|---|
| 10/28 | "2025만 보고 약한 구간부터 진단하라" | 범위를 벗어난 날의 81~91%가 '월 단위 가격 수준 변화'에서 나온다는 것을 찾음 |
| 11/03 | "변동비를 꾸준히 모을 수 없으면 대신 쓸 공개 자료를 찾아라" | 가스공사 발전용 요금이 매달 공개(전달 26~27일 게시)됨을 확인 |
| 11/03 | "모델 비교와 함께 변동비·가스요금도 비교하라" (같은 코드에서 하나만 바꿔) | 가스요금 ≈ 변동비, LightGBM 하나 > 두 모델 평균 → 'LightGBM + 가스요금' 확정, 자동 수집 시작 |
| — | (안 통한 것) 시간별 한 달 모델을 밤새 고도화 | 2026 성적이 단순 기준과 비슷. 판단 시점을 '월말'로 바꾼 팀원 방식으로 옮김 |
