> 우리 팀의 코드·데이터는 넘기지 않는다. 데이터는 공공데이터라 03_data.md 순서대로 직접 내려받고(과거분 + 매일 수집), 운영 코드는 여기 적힌 일정·규칙을 기준으로 직접 만든다 (마지막 절에 AI용 프롬프트).
> 우리 결과 웹(https://smp-forecast-1.onrender.com)은 팀 노트북이 돌리는 시연용이라 프로젝트 이후에는 갱신이 멈출 수 있다.

## 0. 먼저 정할 것
- [ ] **어디서 돌릴지**: 매일 켜져 있는 Windows PC 또는 서버 한 대. 주간 전력수요전망 표가 이미지라 OCR이 필요하다 (우리는 Windows 내장 한국어 OCR을 씀).
- [ ] **결과를 어떻게 볼지**: 표·CSV 파일, 사내 공유 폴더의 웹 페이지, 사내 웹서버 등.
- [ ] **누가 매일 확인할지**: 실행 기록 확인 담당 (하루 1분).

## 1. 인증키 직접 발급 (승인까지 하루 이상)
우리 팀이 쓴 키는 팀원 개인 발급이라 넘기지 않는다. 회사 명의로 새로 발급한다.
- [ ] 공공데이터포털(data.go.kr) 일반 인증키 → 활용 신청: 계통한계가격 및 수요예측(하루전 발전계획용), 특일 정보, 기상청 중기예보 조회서비스, 오늘전력수급현황조회, 지역별 시간별 태양광 발전량 정보, 제주계통운영정보
- [ ] 기상청 API허브(apihub.kma.go.kr) 인증키 → 단기예보 구역별 육상예보(`fct_afs_dl`)
- [ ] 키는 코드에 쓰지 말고 별도 설정 파일(예: `.env`)에 둔다.
- 키가 필요 없는 곳: EPSIS, 전력거래소 홈페이지·전력정보앱, 가스공사 요금표, Open-Meteo.

## 2. 하루 일정 (판단 시각 = 15:00)

| 시각 | 할 일 | 왜 |
|---|---|---|
| 15:00 이후 (우리는 15:30) | ① 수집: SMP·수요예측 최근 며칠, 구역예보 11시 발표분, 중기예보 06시 발표분, Open-Meteo, 주간전망 새 게시물, 제주 5분 실적, 가스요금 확인 ② 예측: 일주일 → 한 달(월말만) → 내일 급락·급등 → 근거 문장 → 제주 ③ 결과 저장 | 15시에 공개된 값만으로 판단 (03_data.md 2절) |
| 21:30, 23:50 | 내일 공표 SMP 수집 → 화면에 공표값 표시, 오늘전력수급현황 수집 | 내일 SMP는 저녁에 공표. 수급현황은 오늘분만 줌 |
| 매일 | 실행 기록 확인 | 실패한 단계가 없는지 |

- **늦게 돌아도 같은 결과가 나오게** 만든다: 날씨 예보는 '발표 시각'으로 골라 쓰고, 기준일 15시 이후 자료는 쓰지 않는다. 그래야 PC가 꺼졌던 날을 나중에 따라잡아도 같은 예측이 나온다.
- **그날 못 받으면 사라지는 자료 2개**: 중기예보(당일 발표분만 제공), 오늘전력수급현황(오늘분만 제공). 이 둘은 실패하면 바로 알 수 있게 기록한다.
- PC가 꺼져 있던 날은 켜질 때 밀린 기준일을 차례로 산출한다 (우리는 최대 14일).

## 3. 정기 일정

| 매월 26일 ~ 말일 | 가스공사 다음 달 발전용 요금 게시 확인 (보통 전달 26~27일) |

| 대상 달마다 | 일주일 오차 보정(LightGBM)을 그달 1일까지 자료로 다시 학습 |
| 매년 12월 | 다음 해 특일정보 수집 (임시공휴일은 발표 때 다시) |
| **매년 12월 31일** | **일주일 모델 연 1회 미세조정** (4절) |

## 4. 일주일 모델 연 1회 미세조정 (매년 12/31)
일주일 예측(K3)의 평일 모델은 Chronos-2 small을 **SMP 자료로 1년에 한 번 다시 학습(미세조정)**한 판을 쓴다. 해마다 가격 수준과 하루 모양이 바뀌므로 그해까지의 자료를 반영하기 위해서다. 분기마다 다시 학습해도 차이가 0.004원뿐이라 연 1회로 정했다.

| 항목 | 내용 |
|---|---|
| 언제 | 매년 12월 31일. 그해 12/31까지 자료로 학습한 판을 기준일 12/31부터 다음 해 12/30까지 쓴다 |
| 설정 (바꾸지 않음) | autogluon/chronos-2-small 전체 미세조정, 학습률 1e-6, 500단계, 배치 32, 과거 2,048시간, 공변량 = 휴무일·요일유형·명절, 학습 자료 2022-01 ~ 그해 12/31 |
| 걸리는 시간·자원 | CPU 약 1시간, 메모리를 많이 씀 (16GB 이상 권장). 12/31 오전에 돌려 두면 그날 15시 예측에 바로 쓸 수 있다 |
| 판 고르기 | 기준일이 12/31이면 그해 판, 그 밖에는 전년도 판. 해당 판이 없으면 직전 판으로 예측하고 경고를 남긴다 (멈추지 않음) |
| 보관 | 해마다 판을 따로 저장하고 지우지 않는다 (과거 날짜를 다시 계산할 때 그 시점의 판이 필요) |
| 주의 | 학습률을 높이면(예: 5e-5) 오히려 나빠졌다. 1e-6을 유지한다 |

## 5. 문제가 생기면

| 증상 | 원인·확인 |
|---|---|
| 오늘 예측이 없음 | PC가 꺼졌거나 예약 작업 실패 → 실행 기록 마지막 줄 |
| 수집 실패 | 인증키 만료, 일일 호출 한도(다음 실행에 이어 받기), 사이트 구조 변경 |
| 주간 전력수요전망이 빈칸 | OCR이 이미지를 못 읽음 (우리 경험상 약 10%). 빈칸으로 예측하고 멈추지 않게 |
| 가스요금 수집 오류 | 요금표 페이지가 바뀜 → 주소·파일 형식 확인 |
| 12/31 이후 일주일 경고 "그해 판이 없음" | 미세조정이 안 됨 → 4절을 손으로 실행 |

## 6. 운영 코드를 AI에게 만들게 할 때 붙여 넣을 프롬프트
```
04_follow_prompts.md로 만든 수집·모델 코드를 매일 자동으로 돌리는 운영 코드를 만들어 줘. 첨부한 07_ops_handover.md의 일정·규칙을 따른다.

1. 명령 3개: daily(15:30, 수집 → 예측 → 결과 저장), actuals(21:30·23:50, 내일 공표 SMP·오늘전력수급현황 수집), train(필요할 때 재학습).
2. daily는 '아직 산출하지 않은 기준일'을 스스로 찾아 차례로 산출한다 (최대 14일). 이미 했으면 수집 없이 바로 끝낸다.
   15:00 전에 실행되면 어제 기준일까지만 산출한다.
3. 단계마다 실패해도 다음 단계는 계속하고, 실행 기록 파일에 시각·단계·성공/실패·오류 내용을 남긴다.
   그날만 받을 수 있는 자료(중기예보, 오늘전력수급현황) 실패는 눈에 띄게 남긴다.
4. 예측 결과는 기준일·대상일·시간·예측·하한·상한·실행 시각 열로 기록 파일에 덧붙인다 (같은 기준일을 다시 돌리면 덮어씀).
5. 월말이면 한 달 예측을, 12/31이면 일주일 미세조정(07 4절)을 먼저 하고 예측한다. 대상 달이 바뀌면 일주일 오차 보정을 다시 학습한다.
6. Windows 작업 스케줄러 등록 방법을 알려 줘: 놓친 예약은 켜질 때 바로 실행, 절전 해제, 실패 시 15분 간격 3회 재시도,
   15:30 이후 23:30까지 매시 재시도.
7. 먼저 지난 2주를 기준일로 돌려 보고, 결과가 4~6단계 백테스트와 같은지(같은 기준일끼리) 확인해 보고해.
```
