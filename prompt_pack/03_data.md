# 사용 데이터와 매일 수집할 데이터

> 2026-11-03 기준. 공개된 코드로 같은 결과를 재현하거나 운영할 때 필요한 데이터를 정리했다.
> 저장소에는 **데이터(`data/`)와 API 키(`.env`)가 들어 있지 않다.** 아래 순서대로 직접 받아야 코드가 돈다.

## 1. 한눈에

| 구분 | 데이터 | 처음 한 번 | 매일 | 매일 안 받으면 |
|---|---|---|---|---|
| 가격·수요 | ① 시간별 SMP (육지·제주) | EPSIS 엑셀 + API | API | 다시 받을 수 있음 |
| | ② 하루전 수요예측 (육지·제주) | API (①과 같은 API) | API | 다시 받을 수 있음 |
| | ③ 내일 하루전 수요예측 | ②와 같음 | ②와 같음 | — (수집만, 예측에 안 씀) |
| 달력 | ④ 특일정보 (공휴일·대체·임시·선거일) | API | 12월에 다음 해분 | 다시 받을 수 있음 |
| 수급 전망 | ⑤ 주간 전력수요전망 (최대부하) | 게시판 과거분 수집 | 게시판·앱 | 다시 받을 수 있음 (이미지 OCR) |
| 월 자료 | ⑥ 연료비단가 (LNG·유연탄) | EPSIS | 매월 1~10일 | 다시 받을 수 있음 |
| | ⑦ 시장참여 설비용량 (태양광) | EPSIS 파일 + 수집 | 매월 1~10일 | 다시 받을 수 있음 |
| 날씨 예보 | ⑧ 단기 구역별 육상예보 (11시 발표) | 기상청 API허브 | API허브 | 다시 받을 수 있음 |
| | ⑨ 중기 육상예보 (06시 발표) | 기상자료개방포털 파일 | API | **사라짐** (API가 당일분만 줌) |
| | ⑩ Open-Meteo 과거 실행 예보 | API | API | 다시 받을 수 있음 |
| 제주 실적 | ⑪ 제주 계통 5분 실적 | 내려받은 파일 + API | API | 다시 받을 수 있음 (하루 호출 한도 작음) |
| 쌓는 중 | ⑫ 오늘전력수급현황 (육지 5분) | — | API, 하루 3번 | **사라짐** (API가 오늘분만 줌) |
| | ⑬ 지역별 시간별 태양광 발전량 | 파일데이터 + API | API | 다시 받을 수 있음 (약 7주 늦게 갱신) |

- 팀 합의로 **이 13종만** 쓴다. 이 밖의 자료(변동비 순위, 발전원별 실적, 원전 정비계획, 출력제어 등)는 실험만 했고 채택하지 않았다 (6절).
- **⑨ 중기예보와 ⑫ 오늘전력수급현황은 그날 받지 않으면 다시 구할 수 없다.** 운영을 시작하면 하루도 빠뜨리지 않는 것이 가장 중요하다.

## 2. 먼저 준비할 것

### 2.1 API 키
저장소 루트에 `.env` 파일을 만들고 아래 두 줄을 넣는다 (`.env`는 커밋하지 않는다).
```
DATA_GO_KR_API_KEY=공공데이터포털 일반 인증키(Decoding)
KMA_APIHUB_KEY=기상청 API허브 인증키
```

| 키 | 받는 곳 | 활용 신청할 서비스 |
|---|---|---|
| `DATA_GO_KR_API_KEY` | 공공데이터포털 (data.go.kr) | 한국전력거래소_계통한계가격 및 수요예측(하루전 발전계획용) · 한국천문연구원_특일 정보 · 기상청_중기예보 조회서비스 · 한국전력거래소_오늘전력수급현황조회 · 한국전력거래소_지역별 시간별 태양광 발전량 정보 · 한국전력거래소_제주계통운영정보 |
| `KMA_APIHUB_KEY` | 기상청 API허브 (apihub.kma.go.kr) | 단기예보 구역별 육상예보 (`fct_afs_dl`), 2023분 중기예보 보강 (`fct_afs_wl`) |
| 필요 없음 | EPSIS (epsis.kpx.or.kr), 전력거래소 홈페이지, Open-Meteo | — |

- 공공데이터포털은 서비스마다 따로 활용 신청해야 하고, 승인까지 하루 이상 걸릴 수 있다.
- 일부 서비스는 하루 호출 한도가 작다(약 100회). 수집기는 한도에 걸리면 멈추고, 다음 실행 때 이어서 받는다.

### 2.2 직접 내려받아 넣을 파일 (`data/raw/`에 그대로 둔다)
수집 코드가 이 파일 이름 규칙으로 찾으므로 **이름을 바꾸지 않는다.**

| 파일 | 받는 곳 | 내용 |
|---|---|---|
| `smpInLand_2022.xlsx` ~ `smpInLand_2026.xlsx` | EPSIS 계통한계가격(SMP) 시간별 육지, 연도별 엑셀 내려받기 | 확정 SMP. 엑셀 이후 날짜는 API 공표값으로 채움 |
| `smpJeju_2022.xlsx` ~ `smpJeju_2026.xlsx` | 같은 화면에서 제주 | 제주 확정 SMP |
| `FCT_MEDM_*.csv` | 기상자료개방포털 (data.kma.go.kr) 중기 육상예보 과거 자료 | 중기예보 과거분 (API는 과거를 주지 않음) |
| `HOME_전력거래_시장참여설비용량(전력시장·PPA)_연료원별.csv` | EPSIS 시장참여설비용량 연료원별 내려받기 | 설비용량 과거분 (이후는 수집기가 이어 받음) |
| `한국전력거래소_지역별 시간별 태양광 및 풍력 발전량_*.csv` | 공공데이터포털 파일데이터 15065269 | 2025년까지 지역별 태양광 (이후는 API) |
| `chejusukub*.csv`, `제주계통운영정보_23.csv` | 전력거래소 제주계통운영정보 내려받기 | 제주 5분 실적 과거분 |

- 파일 인코딩은 대부분 cp949(엑셀에서 저장한 그대로)다. 열 이름·단위·시간 표기(1~24시)는 원본 그대로 두면 코드가 처리한다.

## 3. 데이터별 상세

열 설명: **판단 시각에 쓰는 규칙** = 내일 예측을 전날 15:00에 낸다는 가정에서, 그 시각에 이미 공개된 값만 쓰도록 맞춘 규칙. **쓰는 곳**의 일주일·한 달은 모델 확정 후 갱신한다 (일주일 K3도 이 13종 안에서만 씀).

| # | 데이터 | 출처 | 수집 명령 (처음 / 매일) | 판단 시각에 쓰는 규칙 | 쓰는 곳 |
|---|---|---|---|---|---|
| ① | 시간별 SMP | EPSIS 엑셀 + data.go.kr `SmpWithForecastDemand` | 처음 `python -m common.collect.smp_forecast` (2020년부터 전체, 약 8분) / 매일 `… smp_forecast --recent 5` | 전날(D-1)까지의 실적만. 내일 SMP는 평일 19~20시(늦으면 23시), 토·일 14시 전 공표라 15시엔 모름 | 전부 |
| ② | 하루전 수요예측 (육지 `mlfd`, 제주 `jlfd`) | ①과 같은 API | ①과 같음 | D-1일분까지만 (D일분은 공표가 늦음) | 급락, 급등, 제주 |
| ③ | 내일 하루전 수요예측 | ①과 같은 API | ①과 같음 | **예측에 쓰지 않음** (15시 판단 기준, 수집만) | — |

## 4. 매일 수집 일정

| 시각 | 받는 것 | 이유 |
|---|---|---|
| 매일 15:00 전후 (판단 직전) | ① SMP·② 수요예측 최근 5일, ⑧ 구역예보 11시 발표분, ⑨ 중기예보 06시 발표분, ⑩ Open-Meteo, ⑤ 주간전망 새 게시물, ⑪ 제주 5분, ⑫ 수급현황 | 15시 판단에 필요한 자료를 모두 모은 뒤 예측 |
| 매일 21:30, 23:50 | ① 내일 공표 SMP·수요예측, ⑫ 수급현황, ⑬ 지역별 태양광 | 내일 SMP는 저녁에 공표 → 공표값으로 교체. ⑫는 23:50이 그날 마지막 |
| 매월 1~10일 | ⑥ 연료비, ⑦ 설비용량 | 월 1회 갱신 |
| 매년 12월 | ④ 다음 해 특일정보 | 임시공휴일은 발표되면 다시 받기 |

- 우리 운영은 위 일정을 `python -m smp_forecast_app.src.ops daily`(15:30) · `ops actuals`(21:30·23:50)가 한 번에 돌린다. 수집 명령만 따로 써도 된다.
- 수집이 하루 늦어도 결과는 같다 (②⑧⑨처럼 발표 시각이 정해진 자료를 날짜로 골라 쓰기 때문). **⑨·⑫만 예외**로 그날 받아야 한다.

## 5. 저장 위치

| 위치 | 내용 |
|---|---|
| `data/raw/` | 2.2의 직접 내려받은 파일 (수정 금지) |
| `data/raw/api/{자료}/` | 수집기가 받은 원문 (`smp_forecast/`, `holidays/`, `kma_afs/`, `mid_fcst/`, `openmeteo/`, `openmeteo_jeju/`, `epsis_fuel_cost/`, `epsis_capacity/`, `kpx_jeju_sukub/`, `kpx_sukub/`, `kpx_pv_region/`) |
| `data/raw/kpx_weekly_outlook/` | 주간전망 게시 이미지와 목록 |
| `data/raw/surge_extra/openmeteo_best/` | 급등용 Open-Meteo (기온·운량·강수·일사) |
| `data/processed/` | 정제 결과 (코드가 위 원문에서 다시 만듦) |

- 모든 코드는 `common/loaders.py`의 읽기 함수를 거친다. 새 자료를 넣으려면 같은 폴더·이름 규칙을 따르면 된다.
