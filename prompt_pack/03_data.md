# 사용 데이터와 매일 수집할 데이터

> 2026-11-03 기준. 우리 예측(내일 급락·급등 경보, 일주일, 한 달)에 쓴 데이터와, 운영하려면 매일 모아야 하는 데이터를 정리했다.
> 이 문서만으로 같은 데이터를 직접 모을 수 있도록 출처·받는 법·주의할 점을 적었다.
> 맨 아래 7절에는 AI 코딩 도우미에게 수집 코드를 만들게 할 때 붙여 넣을 프롬프트를 넣었다. 모델 만들기는 04_follow_prompts.md.

## 2. 가장 중요한 규칙: 판단 시각 = 전날 15:00

모든 예측은 **전날(D-1) 15:00에 그 시각까지 공개된 값만** 써서 낸다. 데이터마다 "언제 공개되나"가 달라서 아래처럼 맞췄다.

| 데이터 | 15시 판단에 쓰는 범위 | 이유 |
|---|---|---|
| ① SMP | D-1일까지 실적 | 내일 SMP는 평일 19~20시(늦으면 23시), 토·일 14시 전 공표. 화요일은 늦거나 빠지기도 함 |
| ② 하루전 수요예측 | D-1일분까지 | D일분(③)은 내일 SMP와 같은 시각에 공표 → 15시엔 없음 |
| ⑤ 주간 전력수요전망 | 게시 **다음 날**부터 | 게시 시각이 일정하지 않음 |
| ⑥ 연료비단가 | **M월 값을 M+2월 1일부터** | 공개가 늦음 |
| ⑦ 설비용량 | M월 값을 M+2월 1일부터 | 공개가 늦음 |
| ⑧ 단기 구역별 육상예보 | D-1일 **11시 발표분** (없으면 05시), 1~3일 뒤 | 14시 발표분은 15시 전 확보가 불확실 |
| ⑨ 중기 육상예보 | **06시 발표분**, 4일 뒤부터 | 1~3일 뒤는 ⑧로 |
| ⑩ Open-Meteo | **2일 이상 전에 실행된 예보만** (D일 값 = D-2 실행분) | 하루 전 실행분은 공개 시각이 섞여 있음 |
| ⑪ 제주 5분 실적 | 판단일 14:25까지 | 실시간 공개 |

- 실측 날씨나 당일 실적으로 만든 결과는 '상한선 성능'으로만 따로 보고, 실제 성능으로 쓰지 않았다.
- 늦게 수집해도 같은 값을 고를 수 있도록 **발표 시각과 수집 시각을 함께 저장**한다.

## 3. 데이터별 받는 법

### ① 시간별 SMP · ② 하루전 수요예측 · ③ 내일 하루전 수요예측
- **과거 확정값**: EPSIS(epsis.kpx.or.kr) 계통한계가격(SMP) 시간별, 육지·제주 각각 연도별 엑셀 (2022~).
- **API**: 공공데이터포털 「한국전력거래소_계통한계가격 및 수요예측(하루전 발전계획용)」
  `https://apis.data.go.kr/B552115/SmpWithForecastDemand/getSmpWithForecastDemand`
  - 하루 48행 (24시간 × 육지/제주). 열: `date`(YYYYMMDD), `hour`(**1~24시**), `areaName`(육지/제주), `smp`(원/kWh), `mlfd` 육지 수요예측, `jlfd` 제주 수요예측, `slfd` 합계 (MW).
  - 날짜 없이 부르면 2020-01-01 ~ 내일 전체를 **최신순**으로 준다 (한 번에 5,000건, 전체 약 8분). 그 뒤로는 최근 5일 ~ 내일만 날짜 지정으로 다시 받아 합친다.
  - 엑셀이 끝난 뒤의 날짜는 API 공표값을 쓴다.

### ④ 특일정보
- 공공데이터포털 「한국천문연구원_특일 정보」 `getRestDeInfo` (연·월 단위).
- 공휴일·대체공휴일·임시공휴일·선거일. 여기서 휴무일, 연휴 길이, 명절, 징검다리(휴일 사이 평일)를 만든다.
- 2026년부터 노동절(5/1)·제헌절(7/17)이 공휴일. 임시공휴일은 발표되면 다시 받는다.

### ⑤ 주간 전력수요전망
- 전력거래소 게시판 「주간 전력수요 전망」 (매주 마지막 근무일 게시): 대상 9일(토 ~ 다음 주 일)의 예측 최대부하(GW)·기온.
  **2025-09 이후 표가 PNG 이미지**라 OCR로 읽는다 (우리는 Windows 내장 한국어 OCR, 3배 확대. 과거 55건 검증: 일치 89%, 못 읽음 11% → 빈칸 처리).
- 전력정보앱 주간 수급전망: 다음 주 평일 5일 최대전력(MW)을 텍스트로 준다 → 평일은 이 값을 우선.
- 과거 게시물(2022-12 ~)도 게시판 목록을 따라가며 받는다.

### ⑥ 연료비단가 · ⑦ 시장참여 설비용량
- EPSIS 연료비용: 연료원별(원자력·유연탄·무연탄·유류·LNG) 원/kWh, 월별. 2020-01 ~. 매월 1~10일 사이 갱신 확인.
- EPSIS 시장참여 설비용량 연료원별 (태양광 MW만 사용), 월별. 과거분은 화면에서 내려받은 csv, 이후는 같은 화면 자료를 매월 받는다.
- 둘 다 키 없이 EPSIS 화면 자료를 받는다.

### ⑧ 단기 구역별 육상예보
- 기상청 API허브 `fct_afs_dl` (키 필요). 발표 05·11·17시, 발표일부터 3~4일 뒤까지 오전·오후.
- 항목: 하늘상태(맑음 ~ 흐림), 강수확률(%), 기온, 강수 유무. 제주는 풍향도 사용.
- 지점(구역 코드): 육지 7곳 서산 11C20101, 전주 11F10201, 광주 11F20501, 목포 21F20801, 안동 11H10501, 대구 11H10701, 진주 11H20701 / 제주 11G00201, 서귀포 11G00401.
  (태양광이 많은 지역 위주. 이 7곳 평균이 11개 지점 평균과 거의 같음)
- 과거 발표분도 기간을 지정해 받을 수 있다 (2023-01 ~).

### ⑨ 중기 육상예보
- **과거분**: 기상자료개방포털(data.kma.go.kr) 중기 육상예보 파일 내려받기. 2023분 빈 곳은 기상청 API허브 `fct_afs_wl`로 보강.
- **매일**: 공공데이터포털 「기상청_중기예보 조회서비스」 `getMidLandFcst`, 06시 발표분(`tmFc=YYYYMMDD0600`).
  **오늘 발표분만 준다 → 매일 받아 쌓아야 한다.**
- 권역 10곳: 서울·인천·경기 11B00000, 강원영서 11D10000, 강원영동 11D20000, 충남 11C20000, 충북 11C10000, 전남 11F20000, 전북 11F10000, 경북 11H10000, 경남 11H20000, 제주도 11G00000.
- 항목: 4~10일 뒤 오전·오후 하늘, 강수확률 (8일 뒤부터는 하루 1개).

### ⑩ Open-Meteo 과거 실행 예보
- Open-Meteo Previous Runs API `https://previous-runs-api.open-meteo.com/v1/forecast` (키 없음, 비상업 무료).
- 변수 이름 뒤에 `_previous_day2`를 붙이면 **그 시각보다 2일 전에 실행된 예보**를 준다 → 판단 시각에 확실히 있던 값.
- 육지 7개 도시(⑧과 같은 지역 좌표): 일사(`shortwave_radiation`)·운량(`cloud_cover`), 모델 JMA·ECMWF IFS 0.25·GFS.
  급등 경보는 모델 지정 없이(best_match) 기온·운량·강수·일사.
- 제주 4지점(제주·고산·성산·서귀포): 위 + 풍속 10m·100m.
- 2024-01 ~ 사용 (2023년은 일부 모델만 있어 쓰지 않음).

### ⑪ 제주 계통 5분 실적
- 과거분: 전력거래소 제주계통운영정보 내려받은 파일 (2024-01 ~).
- API: 공공데이터포털 「한국전력거래소_제주계통운영정보」 (15158505). 호출 1회 = 하루 288행.
- 열: 공급능력, 발전단 수요, 송전단 수요(2026-06 이전 0), 신재생 합계, 태양광, 풍력 (MW). **하루 호출 한도가 작다(약 100회).**

### ⑫ 오늘전력수급현황 (육지 5분) — 쌓는 중
- 공공데이터포털 「한국전력거래소_오늘전력수급현황조회」 `getSukub5mToday`.
- 열: 현재수요, 공급능력, 공급·운영예비력(률), 당일 최대 예측수요 (MW, %).
- **오늘분만 준다** → 15:30·21:30·23:50에 받아 하루 전체를 남긴다. 2026-10-26부터 쌓는 중이라 아직 예측에 쓰지 않는다.

### ⑬ 지역별 시간별 태양광 발전량 — 쌓는 중
- 과거분: 공공데이터포털 파일데이터 15065269 (시·도별 시간별, 2021 ~ 2025).
- API: 「한국전력거래소_지역별 시간별 태양광 발전량 정보」 `getPvAmountByLocHr`. 날짜 인자를 무시하고 **전체를 최신순**으로 준다 → 마지막으로 받은 날짜보다 새 것만 받고 멈춘다.
- **약 7주 늦게 갱신**되는 실적이라 판단 시각 규칙을 따로 정해야 해서 아직 예측에 쓰지 않는다.

## 4. 필요한 인증키

| 키 | 받는 곳 | 활용 신청할 서비스 |
|---|---|---|
| 공공데이터포털 일반 인증키 | data.go.kr | 계통한계가격 및 수요예측(하루전 발전계획용), 특일 정보, 기상청 중기예보 조회서비스, 오늘전력수급현황조회, 지역별 시간별 태양광 발전량 정보, 제주계통운영정보 |
| 기상청 API허브 인증키 | apihub.kma.go.kr | 단기예보 구역별 육상예보 `fct_afs_dl`, (2023 보강) `fct_afs_wl` |
| 필요 없음 | EPSIS, 전력거래소 홈페이지·전력정보앱, Open-Meteo | — |

- 공공데이터포털은 서비스마다 따로 신청하고, 승인까지 하루 이상 걸릴 수 있다.
- 키는 코드에 직접 쓰지 말고 별도 설정 파일(예: `.env`)에 둔다.

## 5. 매일 수집 일정

| 시각 | 받는 것 | 이유 |
|---|---|---|
| 매일 15:00 전후 (판단 직전) | ①② 최근 5일, ⑧ 11시 발표분, ⑨ 06시 발표분, ⑩, ⑤ 새 게시물, ⑪ 최근 3일, ⑫ | 15시 판단에 필요한 자료를 모은 뒤 예측 |
| 매일 21:30, 23:50 | ①③ 내일 공표 SMP·수요예측, ⑫, ⑬ 새 날짜 | 내일 SMP는 저녁에 공표 → 화면을 공표값으로 교체. ⑫는 23:50이 그날 마지막 |
| 매월 1~10일 | ⑥, ⑦ | 월 1회 갱신 |
| 매년 12월 | ④ 다음 해분 | 임시공휴일은 발표 때 다시 |

- PC가 꺼져 하루 늦게 받아도, 발표 시각으로 골라 쓰는 자료는 결과가 같다. **⑨·⑫만 그날 받아야 한다.**

## 6. 시험했지만 쓰지 않는 자료

| 자료 | 결과 |
|---|---|
| 변동비 순위 (발전기별 월별, 2026-10-30 공유) | 급락·급등·일주일 모두 2025 검증에서 개선 없음 → 미채택. 2024 ~ 2026.10은 직도입 LNG 변동비 계단이 101~116원으로 거의 움직이지 않아 효과를 확인할 시기가 없었다. 계단이 크게 바뀌는 달(예: 2026-11)이 쌓이면 다시 볼 후보. 그때 쓰려면 **매월 꾸준한 공개·수집**이 필요하다 |
| 발전원별 5분 실적, 원전 계획예방정비, 태양광·풍력 출력제어 | 일주일·급락 실험에서 탈락 |
| 기상청 단기예보 격자 14시 발표분 | API가 최근 3일만 줘서 과거 비교 불가 |
| 전력수급예보 (내일 최대 예측수요) | 과거 조회 불가, 15시 전 공개 여부 미확인 |
| 실측 날씨 (ASOS) | 판단 시각에 알 수 없음 → 상한선 비교용만 |

## 7. 수집 코드를 AI에게 만들게 할 때 붙여 넣을 프롬프트

```
SMP 예측에 쓸 데이터 수집 코드를 만들어 줘. 데이터 목록·출처·판단 시각 규칙은 첨부한 03_data.md를 따른다.

먼저 할 일:
1. 03_data.md 1·3절의 13종 중 ①②④⑥⑦⑧⑨⑩부터 (육지만). 인증키는 .env에서 읽고 코드에 쓰지 않는다.
2. 자료마다 수집 스크립트를 따로 만들고, 받은 원문은 data/raw/api/{자료}/ 아래에 월별 파일로 저장한다. 이미 받은 기간은 건너뛰고, 호출 한도에 걸리면 멈췄다가 다음 실행에 이어 받는다.
3. 날씨 예보(⑧⑨⑩)는 '발표 시각(또는 실행 시각)'을 반드시 함께 저장한다. 나중에 "D-1 15시에 이미 있던 값"만 고를 수 있어야 한다.
4. 열 이름·단위·시간 표기(1~24시 vs 0~23시)·인코딩은 추측하지 말고 실제 응답을 열어 확인한 뒤 정리한다.

그다음:
5. 읽기 함수 하나에 모아, 날짜별로 '판단 시각(D-1 15:00)에 알 수 있던 값'만 돌려주게 만든다. 03_data.md 2절 표의 규칙(연료비 M+2월, 주간전망 게시 다음 날, 구역예보 11시 발표분, Open-Meteo 2일 전 실행분)을 그대로 적용한다.
6. 2023-01 ~ 오늘까지 과거분을 받고, 자료별로 기간·빈 날짜·이상값을 표로 보고한다.
7. 매일 실행할 순서를 03_data.md 5절 일정대로 한 파일에 묶는다. ⑨ 중기예보는 그날 받지 않으면 사라지므로 실패하면 기록이 남게 한다.

단계마다 결과를 요약해 보고하고, 내가 확인한 뒤 다음 단계로 간다.
```
