# 규칙 정리

> 2026-10-28 기준. 원본은 저장소 루트 [CLAUDE.md](../CLAUDE.md)(팀 공통 규칙)와 [ROLES.md](../smp_forecast_app/docs/ROLES.md)(역할·산출 형식)이다. 여기는 그 내용을 한곳에서 읽기 쉽게 묶은 요약이다. 둘이 다르면 원본이 맞다.

## 1. 프로젝트 한눈에
- **목적**: 한국중부발전 동반성장부가 운영 중인 SMP(계통한계가격) 예측 프로그램(LightGBM)의 부족한 점 개선 (숙명여대 P4 산학).
- **과제**: ① 내일 급락 경보 ② 시간별 예측에 80% 범위를 붙인 웹앱 ③ 예측 근거 문장 ④ 내일 급등 경보.
- **화면에 나가는 예측**: 내일 급락 경보 · 내일 급등 경보 · 일주일 예측(시간별) · 한 달 예측(일별, 참고 전망). 육지·제주 각각.

## 2. 팀 공통 규칙 (모든 과제 문서보다 우선)
1. **데이터 13종만** 쓰고 매일 수집한다: 시간별 SMP, 하루전 수요예측, 내일 하루전 수요예측(수집만, 피처로 안 씀), 특일정보, 주간 전력수요전망, 연료비단가, 시장참여 설비용량, 단기 구역별 육상예보, 중기 육상예보, Open-Meteo 과거 실행 예보, 제주 계통 5분 실적, 오늘전력수급현황, 지역별 시간별 태양광.
2. **기간**: 2023~2026 사용. 선택은 2023~2024 학습 → 2025 검증, 그다음 2023~2025로 다시 학습 → **2026으로 한 번 채점**.
3. **급락 = 모든 날(평일 포함)**, 11~15시 최저 SMP 30원 미만. 학습·문턱·성적 모두 전체 날, 휴일·주말은 참고 행. (10/26 '휴일·주말만' → 10/28 현업 답변으로 되돌림)
4. **공식 성적 기간** = 2026-01-01 ~ 10-18. 팀 비교표는 같은 기간·같은 지표로 나란히 낸다.

## 3. 평가 공정성 (현업 요구)
- **시험 구간(2026-01-01 이후)으로 모델·피처·문턱을 고르거나 반복 튜닝하지 않는다.** 고르는 근거는 2025 이전, 2026은 마지막에 한 번.
- **판단 시각 = 전날 15:00.** 내일 SMP·수요예측은 평일 19~20시(늦으면 23시), 토·일 14시 이전에 공표되므로 15시 판단에 쓸 수 없다. 공표되면 웹은 예측 대신 공표값을 보여 준다(21시 2차 예측은 하지 않음, 현업 10/28).
- 날씨는 15시 이전에 발표된 예보만: 구역별 육상예보 11시 발표분, 중기예보 06시, Open-Meteo 2일 전 실행분.
- 실측 기상·당일 실적으로 만든 결과는 **'상한선 성능'**으로 따로 표기하고 최종 성능으로 보고하지 않는다.

## 4. 데이터·코드 작업 규칙
- **누수 금지**: 피처는 D-1 15시에 알 수 있는 값만. 피처마다 "D-1 몇 시에 확보되나"를 확인, 불확실하면 묻는다.
- 전처리 통계(스케일링·결측 대체)는 학습 구간에서만 적합. **시간 순서 분할만**, 랜덤 분할·셔플 K-fold 금지.
- 컬럼명·단위·시간 표기(1~24시 vs 0~23시)·인코딩은 **추측하지 말고 파일을 열어 확인**.
- `data/raw/`는 원본 보관(수정 금지), 가공 결과는 `data/processed/`. 담당자 기존 프로그램 폴더 `data/smp_edu_data/`는 수정 금지.
- API 키는 `.env`(커밋 금지). 시드 `SEED = 42`. 각 단계는 독립 실행 가능한 스크립트로.
- 두 과제 이상이 쓰는 코드는 `common/`. 휴일 처리는 `common/`에 한 번만.
- 그래프·주석·보고는 한국어, 한글 폰트는 공통 유틸.

## 5. 진행 방식 (사람과 AI가 같이 일하는 규칙)
- **단계마다 보고 → 사용자 확인 → 다음 단계.** 큰 결정은 채점 전에 규칙을 먼저 정하고 확인받는다.
- 정의·범위를 바꾸면 각 과제 `docs/PLAN.md`의 **결정 기록**(날짜·결정·근거)에 남긴다.
- 커밋·푸시는 사용자가 요청할 때만.

## 6. 역할 분담 (채팅 하나 = 역할 하나)
| 역할 | 맡는 일 | 고치는 곳 |
|---|---|---|
| R0 총괄·웹·운영 | 결과 취합, 웹, 매일 운영(15:30 예측, 21:30·23:50 공표값 수집, 일요일 재학습) | `smp_forecast_app/src/ops.py`·`export_web.py`·`team_scorecard.py`, `web_src/`, `web/`, `common/collect/`, 과제2 문서 |
| R1 급락 (육지) | 팀 합의 구성(LSTM + LightGBM) 구현·다듬기 | `drop_classifier/`, `ops_drop.py`에 함수 추가만 |
| R2 제주 | 제주 급락·가격 | `jz_*.py`, `drop_classifier/src/jeju_*.py`, `JEJU.md` |
| R3 일주일 | 평가 범위 진단 → 고도화 | 새 파일 `wz3_*`, `WEEK_V3.md` |
| R4 급등 | 팀 합의 구성(3모델 평균) 구현·다듬기 | `surge_classifier/` |
| R5 근거 문장 | 경보 옆 "왜" 문장 | 새 파일 (총괄과 형식 협의) |
| R6 한 달 | 평가 범위 진단 → 고도화 | 새 파일 `mx3_*`, `MONTH.md` 새 절 |

- 다른 역할의 파일은 **읽기만**. 공용 코드는 **인자 추가(기본값 = 지금 동작)**로만 바꾸고 기존 출력이 같은지 확인.
- 시험 실행은 `SMP_NO_PUSH=1`, 운영 기록 폴더는 건드리지 않는다.
- 산출 형식(ROLES.md 4절): 경보는 `{kind}_{계통}_15h.csv`(base_date, date, grade, prob, score, label) + 설정 json + 성적표 + 운영 함수 `predict(bases)`. 가격은 시간별 예측·하한·상한 + 표준 지표(MAE·포함률·구간점수 등).
- 표기: 경보 단계 **없음 / 주의 / 경보**. 재현율 = 실제 급락일 중 미리 경보한 비율, 정밀도 = 경보한 날 중 실제 급락 비율.

## 7. 2026-10-28 현재 결정
- **급락·급등 모델 구성은 팀 합의로 고정**, 세부(피처·설정·결측·보정·문턱 세부)는 우리가 정한다(팀원 설정은 받지 않음).
  - 육지 급락 = LSTM + LightGBM(확장 변수) 평균
  - 급등 = 부호 고정 점수 + 스플라인 로지스틱 + LightGBM 그루터기 평균
- **일주일·한 달은 고도화**: 성능이 보는 범위(시간대·지평·계절)에 따라 달라서 평가 범위 진단부터.
- 일정: 11/4 대면(성공 기준 확정) → 11/11 공동 발표(팀별 5분).
