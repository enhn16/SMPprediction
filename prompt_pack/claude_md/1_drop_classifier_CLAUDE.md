# 과제1: SMP 한낮 급락 판단

> 공통 규칙은 루트 [CLAUDE.md](../CLAUDE.md)를 따른다. 매 세션 이 파일과 [docs/PLAN.md](docs/PLAN.md)를 읽고, 체크리스트에서 현재 진행 단계를 확인한 뒤 작업한다.

## 1. 과제 맥락

- **목적**: 기존 SMP 예측은 전체 흐름은 맞지만 한낮 SMP 급락을 예측하지 못함. 이를 보완하는 급락 판단 모델.
- **핵심 질문**: "내일 한낮에 SMP가 급락하는가?"를 **전날** 예측하는 **이진 분류**.
- **범위**
  - 가격 수준 예측은 하지 않는다 (과제2에서 별도로 다룸). **급락 여부 판단만** 한다.
  - **급락은 모든 날(평일 포함)** 이 대상이다 — 학습·문턱·판정·성적 전부 전체 날, 휴일·주말은 성적표 참고 행 (2026-10-28 현업 답변: 제주 평일 12시 0원 발생. 10/26 '휴일·주말만' 규칙 폐지).
  - 대상 계통: **육지**와 **제주**. 레이블·피처·모델은 계통별로 따로 만든다 (1-1 참조).
- **실패 사례 (육지, 반드시 검증 기간에 포함하여 개별 확인)**
  | 날짜 | 상황 | 실제 | 기존 예측 |
  |---|---|---|---|
  | 2026-09-25 | 추석 연휴, 12시 | 0원 | 72.65원 |
  | 2026-10-05 | 흐린 연휴, 한낮 | 106원대 | 평균 68원 |
- **가설**: "휴일이면 떨어진다"가 아니라 **낮은 수요(휴일 등) + 맑음(태양광) 등 조건 조합**이 급락의 핵심. 평일에도 조건이 맞으면 급락한다 (특히 제주).
- **기존 모델 예측값 파일은 없다.** 위 기존 예측 수치는 문제 배경을 설명하는 참고값일 뿐, 비교 데이터로 쓰지 않는다. 성능 비교는 단순 규칙 기준선(PLAN.md ③)으로 한다.
- 제주 실패 사례는 데이터 확인 후 별도 정리.

### 1-1. 육지와 제주를 분리하는 이유
- 제주는 재생에너지 비중이 매우 높고 출력제어가 잦으며, HVDC로 육지와 연계되어 가격 구조가 다르다.
- 제주는 시장제도 변경(재생에너지 입찰·실시간시장 시범사업 등)으로 **가격 단위(1시간/15분)·가격 범위(음수 가능 여부)·결정 방식이 기간 중에 바뀌었을 가능성**이 있다. 변경 시점과 내용은 실제 데이터와 공식 자료로 확인한 뒤 사용한다.
- 따라서 **육지·제주를 한 모델에 합치지 않는다.** 제주는 제도 변경 전후를 구분해 분석하고, 변경 이전 데이터를 학습에 쓸지 별도로 판단한다.
- 기상 지점, 수요, 재생에너지 발전량도 계통별 값을 사용한다 (제주에 육지 기상·수요를 쓰지 않음). 제주 기상 지점: 제주·서귀포·고산·성산 등.

## 2. 급락 정의

- **판단 단위는 하루.** 시간 단위 레이블 금지 (같은 날 시간들이 묶여 표본이 부풀려짐).
- **육지 레이블**: 11~15시 **육지 SMP** 최저값 < 30원 → 1, 아니면 0.
- **제주 레이블**: 잠정적으로 육지와 같은 정의로 시작하되, 제주 가격 분포(급락 빈도, 0원·음수 발생 여부, 15분 단위 여부)를 확인한 뒤 **창·임계값을 별도로 확정**한다. 급락이 지나치게 흔하면 임계값 조정이나 정의 변경을 사용자와 협의한다.
- 15분 단위 가격이면 한낮 창 안의 최저값을 쓰되, 시간 단위 구간과 비교 가능한지 확인한다.
- 첫 집계 시 10~16시로 넓혀 급락 시간대 분포를 확인한 뒤 창을 확정한다. 확정 전까지 11~15시는 잠정값.

## 3. 데이터 기간과 검증 설계

팀 공통 규칙(루트 CLAUDE.md, 2026-10-26)을 따른다.

- **선택**: 2023~2024 학습 → 2025 검증 (모델·피처·문턱은 여기서만 정한다)
- **최종**: 2023~2025로 다시 학습 → **2026-01-01 ~ 10-18 전체 날 한 번 채점** (지표는 `smp_forecast_app/src/team_scorecard.py`와 같게, 휴일·주말·평일 행을 함께)
- **2023년 자료**: 단기 육상예보는 2023-01부터 수집됨(2026-10-27, 빈 날 1/1), 주간전망은 2022-12 게시분부터 있다. 남은 빈칸(연료비 2023-03 이전 등)은 학습 구간 중앙값으로 채우고, 트리 부스팅은 빈칸 그대로. **'없는 자료'로 넘기기 전에 원본 API·파일에서 그 기간을 받을 수 있는지 먼저 확인한다.**
- 학습·문턱·채점 모두 전체 날 (2026-10-28. 10/26~10/27에는 문턱·채점을 휴일·주말만으로 했음 — 그 결과는 `*_v1_*` 기록).
- (이전 규칙, 대체됨: 2023 제외·2024 학습 → 2025 검증, 2026 상반기·하반기 검증)
- 제주는 제도 변경 시점에 따라 학습 시작일을 조정할 수 있다 (결정 기록에 남김).

## 4. 과제 작업 규칙

- **예측 기준 시각: D-1 15:00** (2026-10-19 변경, 운영 중인 주간 예측과 동일). 날씨 피처는 D-1 11시 발표 단기 육상예보(없으면 05시)만 사용한다 (이전 17시 기준 결과는 폐기 예정).
  - **D일 하루전 수요예측은 쓰지 않는다.** 전력거래소가 평일 19~20시, 토·일 14시 이전에 D일 SMP와 함께 공표. 수요 정보는 D-1일분 이전 수요예측과 주간 전력수요전망(등록 다음 날부터)만 사용.
  - 토·일에는 D일 SMP가 14시 전에 이미 공표되므로, 그날 판단분은 결과 해석 시 주의 (운영 주간 예측도 같은 조건).
  - **판단은 15시 하나** (2026-10-28 현업). 내일 SMP가 공표되면 웹이 공표 한낮 최저로 급락 여부를 바로 보여 준다(총괄 처리) — 21시 2차 모델은 만들지 않는다.
  - **공공데이터로 판단 시각에 알 수 있는 값만 사용한다.**
- **평가 공정성**: 모델·피처·문턱 선택은 2023~2024년 학습 → 2025년 검증으로만 한다. 2026-01-01 이후는 최종 시험으로 한 번만 채점한다 (반복 튜닝 금지).
- **발표 범위**: 하루 전 판단. 일주일 예측은 과제2 참고. 비교 대상은 운영 중인 주간 예측 D+1(15:00, 수요예측 미사용).
- **성공 기준: 과거 급락일 적중률(재현율)과 헛경보 수.** 1순위는 급락을 더 많이 맞히는 것. 판정 임계값은 운영형(재현율 우선)을 쓴다.

- **경보 단계 표기: 없음 / 주의 / 경보** (현업 10/21, ROLES.md 4.3). 경보 = 확신이 큰 날(2025 정밀도 50% 문턱), 주의 = 지켜볼 날(2025 재현율 80% 문턱, 전체 날 기준). 새 산출물은 `경보`로 쓴다. 2026-10-26 이전 파일(`drop_prob_육지.csv`, `13_final_*`, `10_two_tier_*` 등)의 값 `강한 경보`와 json 키 `강한 경보 문턱`은 운영·웹 코드(ops_drop·model_v2·drop_badge·export_web·web_src)가 읽으므로 그대로 두고, 같은 뜻으로 읽는다.
- **모델 구성은 팀 합의로 고정 (2026-10-28)**: 육지 = LSTM + LightGBM(확장 변수) 두 점수의 평균. 두 모델을 빼거나 바꾸지 않는다. 피처·각 모델 설정·결측·확률 보정·문턱 세부는 우리가 정한다(팀원 설정은 받지 않음) — 후보를 채점 전에 정하고 2025 검증으로만 고른다. 이전 운영 모델(Ridge + EBM + 랜덤포레스트)은 `*_v1_ridge_ebm_rf` 기록으로 보관.
- 제주는 지금 KNN 구성을 유지하고 날짜 범위만 전체 날로 바꾼다 (팀 합의 구성 적용 여부는 따로 정함).
- **육지를 먼저 완성하고 제주는 같은 파이프라인을 재사용해 진행한다.** 코드는 계통(`region="육지"|"제주"`)을 인자로 받도록 작성하고, 산출물 파일명에 계통을 표기한다 (예: `daily_label_육지.csv`, `daily_label_제주.csv`).
- 과제2에서 재사용할 수 있도록 최종 급락확률은 `outputs/tables/drop_prob_{계통}.csv` (컬럼: 날짜, 계통, 급락확률, 판정)로 저장한다.
