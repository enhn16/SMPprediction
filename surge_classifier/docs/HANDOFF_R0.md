R4 급등 경보 → R0 총괄 전달 (2026-10-28). 급등 경보 모델을 v3로 교체했고, 산출물과 운영 함수가 준비됐다. 아래 내용을 반영해 줘.

## 1. 무엇이 바뀌었나
- 급등 경보 모델 = **v3** (팀 합의 구성: 부호 고정 점수 + 스플라인 로지스틱 + LightGBM 그루터기 확률 평균).
  - 팀원 spike_simple3를 재구현했다(입력만 팀 13종). 팀원 결과와 날짜별 점수 상관 0.9987, 2026 ~10-02 PR-AUC 0.250 (팀원 0.249).
  - 여기에 헛경보 줄이기 후보 C를 2024~25 검증으로 골라 더했다: 평일×오후 흐림·평일×한낮 운량·주간전망 최대부하 입력 추가, 휴무일엔 주의·경보 없음.
- 판단은 15시 하나. 21시 모델은 없음(공표되면 웹이 공표값으로 교체).
- 경보 문턱은 급락과 같은 규칙으로 계산했다: 주의 = 검증 재현율 80% 최고선, 경보 = 정밀도 50%·적중 2일 / 없으면 정밀도 최고선, 0.01 격자.

## 2. 파일 (surge_classifier/outputs/tables/, ROLES.md 4.1 형식)
- `surge_육지_15h.csv`: 열 `base_date, date, stage(=15h), grade(없음/주의/경보), prob, score, label`
  - 2025-01-01 ~ 내일. 2025는 매달 앞으로만 예측한 값, 2026~는 2023~2025로 학습한 최종 모델 값.
  - label은 모든 날을 채움(급등은 평일·휴일 모두 대상).
- `surge_choice_육지_15h.json`: 모델·피처 40개·부호·문턱(주의 0.43, 경보 0.76)·확률식(Platt a 5.475, b −5.622)·선택 절차·학습 기간.
- `surge_score_육지_15h.csv`: 2024~2025 검증 / 2025 검증 / 2026 시험(~10-18, 참고) × team_scorecard 경보 지표(부트스트랩 95% 구간 포함).
- 예전 파일은 이름을 바꿔 보관만 한다(웹에서 읽지 말 것):
  - 지수식 15시 → `surge_*_15h_v1_index.*`
  - 21시 → `surge_*_21h_v1.*`
  - 예전 운영 함수 → `src/ops_surge_v1.py`

## 3. 운영 함수와 매일 순서
- `from surge_classifier.src.ops_surge import predict` → `predict([오늘])` → DataFrame `[base_date, date, stage, grade, prob, score]` (대상일 = 내일).
- 매일 15:30 전 순서:
  1. 지금 공용 수집 (SMP·수요예측·구역예보 11시분·주간전망·Open-Meteo JMA)
  2. **새로 추가**: `python -m surge_classifier.src.collect_extra openmeteo`
     - Open-Meteo 2일 전 실행 best_match, 육지 7개 도시 기온·운량·강수. 오늘 −10일 ~ 내일+1일을 받는다.
     - 없으면 predict가 "Open-Meteo 예보가 없음" 오류를 낸다.
  3. `predict([오늘])`
- 소요 시간: 입력 표 만들기 약 14초 + 판단 0.06초. 학습한 모델은 `data/processed/surge_classifier/v3_models.pkl`에서 읽는다(매일 다시 학습하지 않음).
- 확인한 것: 2026 백테스트 302일과 등급·점수 모두 일치 (`python -m surge_classifier.src.ops_surge`).

## 4. 성적 요약 3줄
1. 2024~25 검증 (급등 26일): 주의 21일 적중(재현율 81%)·헛경보 218일, 경보 3일 적중·헛경보 7일(정밀도 30%).
2. 2026-01-01 ~ 10-18 (급등 7일, **참고**): 주의 5/7 적중·헛경보 101일, 경보 2/7 적중·헛경보 1일(3번 켜서 2번 맞음). 예전 지수식은 0/7.
3. 팀원 모델(v2)과 같은 급등일을 잡으면서 헛경보는 약 1/3 적다 (2026 주의 151 → 101, 경보 5 → 1).

## 5. 웹·발표 표기 요청
- **2026 성적은 '참고'로 표기**한다. 팀원 모델 구성이 2026 채점을 본 뒤 정해졌고, 우리도 v2의 2026을 본 뒤 C를 골랐다(고른 근거는 검증뿐). 진짜 시험은 2026-10-19 이후.
- 화면에서 두 단계를 다르게 보여 준다.
  - **경보** = 확실한 신호: 빨간 배지, "한 달 0.3번꼴, 2026에 3번 켜서 2번 적중".
  - **주의** = 놓치지 않기 위한 넓은 그물: 옅은 표시, "한 달 약 10번, 켜진 날의 약 5%가 실제 급등(평소 2.4%의 2배)". 현업 우선순위가 '급등일 잡기'라서 주의도 화면에 남기되 경보와 구분한다.
- 시험 기간 차이를 설명할 때: 팀원 수치는 ~10-02(급등 6일, 담당자 파일 끝), 팀 공식은 ~10-18(7일, 10/13 포함).
- 팀 13종 목록의 Open-Meteo 항목에 "기온·강수(급등 v3)"를 추가해 줘(같은 출처·같은 7개 도시, 변수만 추가).
