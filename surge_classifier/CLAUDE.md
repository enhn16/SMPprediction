# 과제4: SMP 급등 판단

> 공통 규칙은 루트 [CLAUDE.md](../CLAUDE.md)를 따른다. 매 세션 이 파일과 [docs/PLAN.md](docs/PLAN.md)를 읽고, 체크리스트에서 현재 진행 단계를 확인한 뒤 작업한다.

## 1. 과제 맥락

- **목적**: 급락의 반대편 — 가격이 평소와 다르게 확 뛰는 날을 전날 판단한다. 과제1(급락)과 같은 3단계(레이블 → 요인 비교 → 분류 모델)로 진행.
- **핵심 질문**: "내일 SMP가 평소보다 크게 오르는가?"를 **D-1 15:00**에 예측하는 **이진 분류**.
- **대상**: 육지 먼저. 휴일 한정 없이 **전체 날짜**, 시간도 하루 전체 (최고가 발생 시각은 따로 기록).
- 계기가 된 사례: 2026-10-13(화, 한낮 176원, 흐려서 태양광 절반), 2026-10-20(화, 19시 한 시간 166원).

## 2. 급등 정의 (현업 기준안, 2026-10-26 수령)

- **그날 최고 SMP ≥ 직전 28일 「일 최고 SMP」 중앙값 × 1.25 → 1** (일 단위)
- 고정 금액(예: 200원)이 아닌 이유: SMP 수준이 연료비에 따라 해마다 다름 (일 최고 중앙값 2022년 210원 → 2025년 138원).
- 직전 28일: 그날 이후 정보를 쓰지 않고 최근 수준을 반영. 기준값은 D-1 15시에 이미 알 수 있다.
- +20%·+30%로 바꿨을 때의 결과도 함께 제시 (민감도).
- **매월 1~3일은 연료비 단가 변경으로 가격 수준 자체가 오를 수 있어 따로 표시** (`is_fuel_change_window`).
- SMP는 전력거래소 원본(2022-01~)만 쓴다. 현업 표(담당자 파일 `smp_dataset_hourly.csv`, 13종 밖)는 2026-10-26에 한 번 재현 확인만 함.
- **판단은 15시 하나** (2026-10-28 현업: 21시 2차 예측 없음). 내일 SMP가 공표되면 웹이 공표 최고가로 급등 여부를 보여 준다(총괄 처리). 공표값은 실제값이라 그것은 '확인'이지 예측 성능이 아니다.

## 3. 평가

- **성공 기준**: 과제1과 동일 — 재현율 80%에서 헛경보 수.
- **모델 구성은 팀 합의로 고정 (2026-10-28)**: 부호 고정 점수 + 스플라인 로지스틱 + LightGBM 그루터기(깊이 1) 세 점수의 평균. 세 모델을 빼거나 바꾸지 않는다. 피처·각 모델 설정·결측·확률 보정·문턱 세부는 우리가 정한다(팀원 설정은 받지 않음).
- 고르는 근거는 검증 구간(2024~2025, 급등일이 적어 두 해)만 → 재학습 → **2026-01-01 ~ 10-18 한 번 채점**. 문턱: 주의 = 검증 재현율 80%, 경보 = 정밀도 50%(없으면 검증 정밀도가 가장 높은 선).
- 이전 모델(지수식: 평일 × 운량·흐림·주간전망, 2026-10-26 채점)과 21시 파일은 `*_v1_*` 기록으로 보관.
- 비교 기준선: 단순 규칙(평일, 평일 + 흐림 예보, 지속성, 기후값).

- 정제 데이터는 `../data/processed/surge_classifier/`에 저장.
- **데이터는 팀 목록만** (루트 CLAUDE.md — 2026-11-03부터 14종, 가스요금은 한 달 예측 전용이라 급등은 13종 안에서, 내일 하루전 수요예측은 피처로 쓰지 않음). 과제1 피처 테이블은 목록 밖 자료(단기예보 격자·ASOS)가 섞여 있어 쓰지 않고, `src/features.py`가 12종으로 새로 만든다.
- 실행 순서 (루트에서): `python -m surge_classifier.src.label_days` → `.features` → `.extra_features` → `.collect_extra openmeteo` → `.team_model2`(팀원 재현) → `.team_model2_fa`(헛경보 후보, 검증) → **`.team_model3`(v3 산출물)** → **`.ops_surge`(운영 함수 검증)**
- 결과 형식은 ROLES.md 4.1 (`kind=surge`, 15시 하나): `outputs/tables/surge_육지_15h.csv`, `surge_choice_육지_15h.json`, `surge_score_육지_15h.csv`, 운영 함수 `src/ops_surge.predict(bases)`. 예전 지수식·21시 결과는 `*_v1_index`·`*_v1`(`models.py`·`ops_surge_v1.py`).

## 5. 지금 모델 (2026-10-28)

- **v3 = 운영 모델** (`src/team_model3.py`): v2 + 평일×오후 흐림·평일×한낮 JMA 운량·주간전망 최대부하 입력(부호 +) + 휴무일 제외. 주의 0.43 · 경보 0.76. 2026 공식: 주의 5/7(헛경보 101), 경보 2/7(헛경보 1). PLAN.md ④-6·④-7.
- v2 = 팀 합의 급등 모델 원형: 팀원 `spike_simple3.py`(reference/급등_코드) 재구현, 입력만 팀 13종 → `src/team_model2.py`. 부호 고정 점수(19개, 난방도·냉방도 +) + 스플라인 로지스틱(37개, C=0.05) + LightGBM 그루터기(200그루, balanced) 확률 평균, 2024~2025 매달 앞으로만 검증, 주의 0.37 · 경보 0.70(규칙 계산).
- 2026 공식(~10-18): 주의 5/7(헛경보 151), 경보 2/7(헛경보 5), PR-AUC 0.220. 우선순위 = 1순위 급등일 잡기, 2순위 헛경보 줄이기 (사용자 결정).
- 이전: 지수식(`models.py`, 산출물은 *_v1_index로 보관 예정), 우리 구현 v1(`team_model.py`, 재현 실패 기록용). 비교는 `compare_versions.py`, 상세는 PLAN.md ④절.
